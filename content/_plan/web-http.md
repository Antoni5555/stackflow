# Курс: Веб и API — шаг 60

**Зачем:** после Django ученик умеет делать страницы, а теперь учится делать и вызывать API: как спроектировать REST, как устроены токены, почему браузер блокирует запрос с другого домена, как надёжно обращаться к чужим сервисам. Основы HTTP (URL, запрос и ответ, методы, коды, cookies, HTTPS) уже пройдены в курсе «HTML, CSS и основы веба» — здесь не повторяем, а углубляем. Курс — мост к DRF и FastAPI (этап 2), а также к Docker и Nginx (порты, коды 502/503, заголовки).
**Контекст:** API магазина для мобильного приложения и партнёров; внешние сервисы — служба доставки и платёжка. Ученик проектирует запросы к API магазина, читает ответы и пишет клиентов на Python.
**Тренажёр:** движок `python`. Настоящие запросы из браузера блокирует CORS, поэтому задачи на `httpx` работают против учебного API магазина через `httpx.MockTransport`. Остальное — `quiz` (какой метод, код, заголовок) и `fix` (собрать или исправить запрос по правилам).
**Опирается на:** Python (раздел «async» — для темы 4.04), HTML, CSS и основы веба (раздел 1), Django (CRUD на страницах, формы, сессии, безопасность).
**Источники:** почти нет — `training_skills/nginx_gunicorn.md` (коды ошибок, `curl`), `КОНСПЕКТЫ/ТЕОРИЯ/FastAPI/FastAPI.docx` (проверить: REST, запросы). Курс пишется с нуля.

Slug курса остаётся `web-http` (курс уже есть в каталоге карточкой «скоро»); название — «Веб и API».

Формат — [docs/content-format.md](../../docs/content-format.md), легенда — [00-overview.md](00-overview.md).

## Перенесено в «HTML, CSS и основы веба» (шаг 20)
Клиент и сервер, URL, DNS и порты, запрос и ответ, `GET`/`POST` и основные коды, cookies и сессии, HTTPS, DevTools — всё, что нужно до Django. Атаки XSS, CSRF, SQL-инъекции разбираются в Django (раздел «Настройки и безопасность»), здесь — только атаки на API.
