# Курс: Терминал и Git: старт — шаг 40

**Зачем:** минимум, чтобы работать с проектом у себя на компьютере: открыть терминал, создать виртуальное окружение, поставить Django, запустить `manage.py` и сохранить работу в Git и на GitHub. Короткий курс перед Django, чтобы не откладывать его. Всё остальное — позже: полный курс Linux (сервер) — перед Docker, глубокий Git — дополнительный модуль.
**Контекст:** ученик начинает проект магазина у себя на компьютере: папка проекта, окружение, зависимости, первый коммит, ветка для новой страницы, публикация на GitHub.
**Тренажёр:** раздел 1 — симулятор shell (движок `linux`), раздел 2 — Git-симулятор (движок `git` поверх Linux-симулятора). У курса один `engine`, поэтому, когда появится Git-симулятор, ставим `git` — в нём есть и терминал. До этого — `quiz`/`fix`.
**Опирается на:** Python (скрипты, модули, импорт).
**Источники:** `КОНСПЕКТЫ/ТЕОРИЯ/Git/Git.docx` (**GIT**) — только порядок тем и факты, текст пишем заново; `training_skills/connect_to_github.md` (SSH), `nginx_gunicorn.md` §3 (venv, pip).

Формат — [docs/content-format.md](../../docs/content-format.md), легенда — [00-overview.md](00-overview.md).

## 2. Git ●○○
| # | Тема | Что разбираем | Задача из магазина | Сырьё |
|---|---|---|---|---|
| 01 | Зачем контроль версий | репозиторий, коммит, история, Git vs GitHub; `git config` | почему нельзя хранить проект как `shop_final_v2.zip` | ✅ GIT «Настройка Git» |
| 02 | Первый коммит | `git init`, `add`, `commit -m`, статусы файлов, `git status` | закоммитить заготовку проекта | ✅ GIT «Работа с репозиторием», «Статусы файлов» |
| 03 | История и изменения | `git log --oneline`, `git diff`, `--staged` | посмотреть правки перед коммитом | ✅ GIT «Команды навигации», «git diff» |
| 04 | `.gitignore` | шаблоны, что не коммитить в Python-проекте | не закоммитить `.env`, `__pycache__`, `venv` | ✅ GIT «Игнорирование файлов» |
| 05 | Ветки и слияние | ветка = указатель, `HEAD`, `git switch -c`, `git merge`, удаление ветки | страница «О магазине» в отдельной ветке | ✅ GIT «Что такое ветка», «Объединяем ветки» ⚠️ `switch` вместо `checkout` |
| 06 | Конфликт | почему возникает, маркеры, разрешение | две ветки поменяли одну строку в `settings.py` | ✅ GIT «Конфликт при слиянии» |
| 07 | GitHub | SSH-ключ, `git remote add`, `push -u`, `clone`, `pull` | отправить проект на GitHub и забрать на другом компьютере | ✅ GIT «SSH», «Отправка», «Клонируем», `connect_to_github.md` |

## Не входит в курс
- Сервер: права, процессы, systemd, SSH на сервер, cron — курс **Linux** (шаг 70, перед Docker).
- Исправление ошибок (`amend`, `restore`, `revert`/`reset`, `stash`), rebase, PR, работа в команде — модуль **Git в команде** (дополнительный).
