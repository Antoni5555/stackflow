Формат — [docs/content-format.md](../../docs/content-format.md), легенда — [00-overview.md](00-overview.md).

## 9. Производительность и транзакции ●●●
| # | Тема | Что разбираем | Задача из магазина | Сырьё |
|---|---|---|---|---|

| 02 | Виды индексов | составной (порядок колонок), уникальный, частичный, по выражению, покрывающий (`INCLUDE`) | индекс только по неотменённым заказам | ✅ D2/03 |
| 03 | EXPLAIN | `EXPLAIN`, `ANALYZE`, Seq Scan vs Index Scan | почему каталог тормозит | ✅ D2/03 ⚠️ проверить вывод в PGlite |
| 04 | Транзакции | `BEGIN/COMMIT/ROLLBACK`, ACID, `SAVEPOINT` | оформление заказа: создать заказ + списать остатки | ✅ D2/04 |
| 05 | Изоляция и MVCC | аномалии, уровни изоляции в PG, MVCC | два покупателя берут последний товар | ✅ D2/04 (теория) ⚠️ пример «Phantom Read в MySQL» заменить |
| 06 | Блокировки | `SELECT … FOR UPDATE`, deadlock | безопасное списание остатка | ✅ D2/04 (теория) |

✅ Написан: `content/backend/sql/09-performance` — 6 уроков, 25 задач (6 `exercise`: 4 `result` — индексы проверяются через `pg_indexes.indexdef`, 1 `state`, 1 `result` с атомарным списанием; 19 `quiz`), 6 рисунков. Планы `EXPLAIN` в уроках сняты в PGlite с `enable_seqscan = on` (как в обычном PostgreSQL; в PGlite по умолчанию `off` — просьба к «Разработке»). Параллельные транзакции (изоляция, блокировки) показаны таблицами по шагам: в PGlite одно подключение. Неточности D2/03–04 исправлены в уроках: «кластеризованный индекс» (MySQL/SQL Server) — в PostgreSQL таблица хранится отдельно, есть только разовый `CLUSTER`; «`user_id = '123'` не использует индекс» — в PostgreSQL литерал без типа становится числом; «Read Uncommitted видит чужие незафиксированные изменения» — в PostgreSQL он равен Read Committed; «Exclusive Lock / FOR UPDATE — никто не может даже читать» — обычный `SELECT` не ждёт (MVCC); «на Serializable чтение ждёт блокировку» — нет, конфликт решается ошибкой сериализации; «Isolation: два человека не купят последний билет» — на Read Committed купят (потерянное обновление); левый префикс: индекс `(a, b)` для условия только по `b` PostgreSQL может прочитать целиком, но это не поиск.
