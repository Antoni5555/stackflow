## Теория
Тип поля модели решает три вещи: какой тип колонки будет в базе, какое значение Python вы получите из объекта и как поле будут проверять формы. Выбор тот же, что при создании таблиц в курсе SQL, только записан классами.

Поля, которые нужны почти в каждой модели магазина:
- **`CharField(max_length=200)`** — короткая строка: название, артикул → `varchar(200)`. Длина проверяется формами и `full_clean()`; база PostgreSQL сама откажет строке длиннее, а SQLite в тренажёре — нет;
- **`TextField()`** — длинный текст без ограничения: описание, отзыв → `text`;
- **`SlugField()`** — адресная часть (`aster-14`): `CharField` с проверкой символов и индексом;
- **`IntegerField()`**, **`PositiveIntegerField()`** — целые числа; у второго база добавит `CHECK ("stock" >= 0)`;
- **`DecimalField(max_digits=10, decimal_places=2)`** — **деньги** → `numeric(10, 2)`, в Python — `Decimal`. Оба параметра обязательны. Для цен никогда не берут `FloatField` (`double precision`): двоичные дробные числа считают с погрешностью, и сумма 0,1 + 0,2 не равна 0,3;
- **`BooleanField()`** — да/нет: «в наличии», «активен»;
- **`DateTimeField()`**, `DateField()` — момент времени (`timestamp with time zone`) и дата. **`auto_now_add=True`** — заполнить временем создания, **`auto_now=True`** — обновлять при каждом `save()`;
- `EmailField()`, `URLField()` — строки с проверкой формата в формах.

Две особенности `auto_now`: поле нельзя задать вручную (Django перезапишет значение при сохранении), и оно **не обновляется** при массовом `QuerySet.update()` — тот идёт в базу прямым `UPDATE` без `save()`.

## Наглядно
**Таблица 1.** Поля Django и колонки PostgreSQL.

| Поле | Колонка PostgreSQL | В Python | Для чего |
|---|---|---|---|
| `CharField(max_length=200)` | `varchar(200)` | `str` | название, артикул |
| `TextField()` | `text` | `str` | описание, отзыв |
| `SlugField()` | `varchar(50)` + индекс | `str` | адрес страницы |
| `PositiveIntegerField()` | `integer` + `CHECK (>= 0)` | `int` | остаток, количество |
| `DecimalField(10, 2)` | `numeric(10, 2)` | `Decimal` | цена, сумма |
| `FloatField()` | `double precision` | `float` | рейтинг, координаты — не деньги |
| `BooleanField()` | `boolean` | `bool` | флаги |
| `DateTimeField()` | `timestamp with time zone` | `datetime` | время событий |
| `DateField()` | `date` | `date` | дата без времени |
| `EmailField()` | `varchar(254)` | `str` | почта |

**Таблица 2.** `auto_now_add` и `auto_now`.

| Параметр | Заполняется | Обновляется при `save()` | При `update()` |
|---|---|---|---|
| `auto_now_add=True` | при создании | нет | нет |
| `auto_now=True` | при создании | да | **нет** |

## На практике
Задача: описать товар полями подходящих типов, проверить, как работают время создания и изменения, и почему цены не хранят во `float`.

### Шаг 1. Модель товара
Файл `models.py`:
```python
from django.db import models


class Product(models.Model):
    name = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200)
    description = models.TextField()
    price = models.DecimalField(max_digits=10, decimal_places=2)
    rating = models.FloatField()
    stock = models.PositiveIntegerField()
    is_active = models.BooleanField()
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    release_date = models.DateField()
    supplier_email = models.EmailField()
```
Таблица в PostgreSQL:
```
CREATE TABLE "shop_product" ("id" bigint NOT NULL PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY, "name" varchar(200) NOT NULL, "slug" varchar(200) NOT NULL, "description" text NOT NULL, "price" numeric(10, 2) NOT NULL, "rating" double precision NOT NULL, "stock" integer NOT NULL CHECK ("stock" >= 0), "is_active" boolean NOT NULL, "created_at" timestamp with time zone NOT NULL, "updated_at" timestamp with time zone NOT NULL, "release_date" date NOT NULL, "supplier_email" varchar(254) NOT NULL);
CREATE INDEX "shop_product_slug_30bd2d5d" ON "shop_product" ("slug");
CREATE INDEX "shop_product_slug_30bd2d5d_like" ON "shop_product" ("slug" varchar_pattern_ops);
```
Все колонки `NOT NULL` — пустые значения разрешают отдельно (следующая тема). Для slug Django сразу создал два индекса: для точного поиска и для `LIKE 'aster%'`.

### Шаг 2. Время создания и изменения
Модель с `name`, `stock`, `created_at` (`auto_now_add`) и `updated_at` (`auto_now`):

Файл `orm.py`:
```python
import time
p = Product.objects.create(name="Мышь")
print(p.created_at == p.updated_at)
time.sleep(0.01)
p.stock = 5
p.save()
print(p.created_at == p.updated_at, p.updated_at > p.created_at)
Product.objects.filter(pk=p.pk).update(stock=7)
p.refresh_from_db()
print(p.stock, p.updated_at)
```
Результат (время у вас будет своим):
```
False
False True
7 2026-11-19 05:26:25.548368+00:00
```
SQL двух изменений:
```
UPDATE "shop_product" SET "name" = 'Мышь', "stock" = 5, "created_at" = '2026-11-19 05:26:25.536017', "updated_at" = '2026-11-19 05:26:25.548368' WHERE "shop_product"."id" = 1
UPDATE "shop_product" SET "stock" = 7 WHERE "shop_product"."id" = 1
```
При создании два поля получили почти одинаковое, но не равное время — каждое берёт своё «сейчас». `save()` обновил `updated_at`, а `update()` изменил только `stock`: время изменения осталось от `save()`.

### Шаг 3. Деньги во float
Модель `Item` с ценой дважды — `FloatField` и `DecimalField`:

Файл `orm.py`:
```python
from decimal import Decimal
Item.objects.create(price_float=0.1, price=Decimal("0.10"))
Item.objects.create(price_float=0.2, price=Decimal("0.20"))
from django.db.models import Sum
Item.objects.aggregate(Sum("price_float"), Sum("price"))
```
Результат:
```
{'price_float__sum': 0.30000000000000004, 'price__sum': Decimal('0.300000000000000')}
```
Сумма `float` — с погрешностью, `Decimal` — точно (лишние нули — особенность SQLite в тренажёре; PostgreSQL вернёт `Decimal('0.30')`).

### Шаг 4. Проверки поля
`Product.objects.create(name="Мышь", stock=-1)` падает в базе: `IntegrityError: CHECK constraint failed: stock`. А название из 300 символов SQLite в тренажёре сохранит. Проверку длины делает `full_clean()` — её вызывают формы:

Файл `orm.py`:
```python
p = Product(name="М" * 300)
p.full_clean()
```
Результат:
```
django.core.exceptions.ValidationError: {'name': ['Убедитесь, что это значение содержит не более 200 символов (сейчас 300).']}
```

## Частые ошибки
- **Цены во `FloatField`.** Погрешности в копейках при сложении и сравнении. Деньги — только `DecimalField` (в Python — `Decimal("1499.00")`, не `1499.0`).
- **`DecimalField` без параметров.** `fields.E130 DecimalFields must define a 'decimal_places' attribute.` и `fields.E132 … 'max_digits' …` — проект не запустится.
- **`TextField` для коротких строк и `CharField` для длинных.** Название — `CharField` с разумной длиной, описание и отзывы — `TextField`.
- **Ждать обновления `auto_now` после `update()`.** Массовое обновление не вызывает `save()`; время меняют явно: `update(stock=7, updated_at=timezone.now())`.
- **Задавать `created_at` руками при `auto_now_add`.** Значение перезапишется при сохранении. Нужна возможность задать дату — `default=timezone.now` вместо `auto_now_add`.

## Итог
**Типы**
- Строки — `CharField(max_length)`, `TextField`, `SlugField`, `EmailField`.
- Числа — `PositiveIntegerField` (с `CHECK`), деньги — `DecimalField(max_digits, decimal_places)`, не `FloatField`.
- `BooleanField`, `DateTimeField`, `DateField`.

**Время**
- `auto_now_add` — при создании, `auto_now` — при каждом `save()`; `update()` их не трогает.

**Проверки**
- Ограничения колонок проверяет база; длину и формат — `full_clean()` и формы.

## Вопросы на собеседовании
<details><summary>Почему деньги хранят в `DecimalField`, а не во `FloatField`?</summary>

`float` хранит дроби в двоичном виде, и большинство десятичных дробей (0,1, 0,2) представимы только приблизительно — суммы и сравнения дают ошибки в копейках. `DecimalField` → `numeric` в базе и `Decimal` в Python: точная десятичная арифметика с заданным числом знаков после запятой.
</details>

<details><summary>Чем `auto_now` отличается от `auto_now_add`?</summary>

`auto_now_add` заполняет поле один раз — при создании объекта. `auto_now` обновляет его при каждом `save()`. Оба не срабатывают при `QuerySet.update()` и `bulk_update()`, а поля с ними не редактируются в формах. Если дату нужно задавать вручную, вместо `auto_now_add` используют `default=timezone.now`.
</details>

<details><summary>Чем `CharField` отличается от `TextField`?</summary>

`CharField` — строка с ограничением длины (`varchar(N)`), в формах — однострочное поле, длина проверяется валидацией. `TextField` — текст без ограничения (`text`), в формах — многострочное поле. В PostgreSQL по скорости разницы нет; выбирают по смыслу.
</details>
