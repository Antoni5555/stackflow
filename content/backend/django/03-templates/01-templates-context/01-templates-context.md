## Теория
Собирать HTML строками в Python неудобно и опасно: кавычки, отступы, а главное — текст покупателя попадает в страницу как есть. Поэтому HTML пишут в **шаблонах** — файлах `.html` с местами для данных. View готовит данные и вызывает **`render(request, "shop/catalog.html", context)`**: Django находит шаблон, подставляет данные из словаря **контекста** и возвращает `HttpResponse` с готовым HTML.

Где Django ищет шаблоны: в папке `templates/` каждого приложения (настройка `APP_DIRS`) и в папках из `TEMPLATES["DIRS"]`. Внутри `templates/` шаблоны кладут в подпапку с именем приложения — `shop/templates/shop/catalog.html`, а в `render` пишут `"shop/catalog.html"`. Причина — все папки `templates/` всех приложений Django просматривает как одну: без подпапки два `catalog.html` из разных приложений перепутаются. Шаблона нет — ошибка `TemplateDoesNotExist`.

Язык шаблонов Django намеренно простой: логика — во view, шаблон только показывает.
- **`{{ переменная }}`** — вывести значение. Через точку — вложенные данные: `{{ product.name }}` ищет сначала ключ словаря, потом атрибут или **метод** (он вызывается без скобок и без аргументов), потом индекс списка: `{{ items.0 }}`. Скобки вызова `{{ cart.total() }}` — синтаксическая ошибка;
- **`{% if %}`… `{% elif %}`… `{% else %}`… `{% endif %}`** — условие: сравнения `==`, `<`, `in`, логика `and`, `or`, `not`;
- **`{% for x in список %}`… `{% empty %}`… `{% endfor %}`** — цикл; `{% empty %}` выводится, если список пуст; внутри доступен `forloop.counter` (номер с 1), `forloop.first`, `forloop.last`;
- **`{# … #}`** — комментарий, в HTML не попадает.

Две особенности, о которых нужно помнить:
- **несуществующая переменная** выводится пустой строкой — без ошибки. Опечатка `{{ prodcut.name }}` просто ничего не покажет;
- **автоэкранирование**: каждое значение в `{{ }}` экранируется — `<`, `>`, `&`, кавычки превращаются в `&lt;` и т. д. Название товара или отзыв с `<script>` покажутся как текст, а не выполнятся. Это главная защита от XSS (курс «HTML, CSS и основы веба», «Спецсимволы и экранирование»). Отключает её фильтр `|safe` — только для своего проверенного HTML, никогда для данных пользователя.

## На практике
Задача: страница каталога из шаблона: номер, название, цена и отметка о наличии; пустой каталог; посмотреть, как шаблон обходится с данными.

### Шаг 1. View
View только готовит данные и передаёт их в `render`:

Файл `views.py`:
```python
from django.shortcuts import render

PRODUCTS = [
    {"name": "Ноутбук Aster 14", "price": 64990, "stock": 5},
    {"name": "Ноутбук Nimbus Air", "price": 54990, "stock": 0},
    {"name": "<b>Мышь</b> со скидкой", "price": 1499, "stock": 40},
]


def catalog(request):
    context = {"products": PRODUCTS, "title": "Ноутбуки и мыши"}
    return render(request, "shop/catalog.html", context)


def empty(request):
    return render(request, "shop/catalog.html", {"products": [], "title": "Пусто"})
```
В названии третьего товара специально оставлен HTML — как будто его ввёл менеджер.

### Шаг 2. Шаблон
Файл `templates/shop/catalog.html`:
```html
<h1>{{ title }}</h1>
{# комментарий шаблона в HTML не попадает #}
<ol>
  {% for product in products %}
    <li>
      {{ forloop.counter }}. {{ product.name }} — {{ product.price }} ₽
      {% if product.stock == 0 %}(нет в наличии){% elif product.stock < 10 %}(мало){% endif %}
    </li>
  {% empty %}
    <li>Товаров пока нет.</li>
  {% endfor %}
</ol>
<p>{{ prodcut.name }}|конец</p>
```
В последней строке — опечатка `prodcut`: посмотрим, что с ней будет.

### Шаг 3. Запросы
Результат (`GET /catalog/`, пустые строки убраны):
```
GET /catalog/ → 200 OK
Шаблон: shop/catalog.html

<h1>Ноутбуки и мыши</h1>
<ol>
    <li>
      1. Ноутбук Aster 14 — 64990 ₽
      (мало)
    </li>
    <li>
      2. Ноутбук Nimbus Air — 54990 ₽
      (нет в наличии)
    </li>
    <li>
      3. &lt;b&gt;Мышь&lt;/b&gt; со скидкой — 1499 ₽
    </li>
</ol>
<p>|конец</p>
```
Три вещи. `<b>` из данных пришёл экранированным — браузер покажет его текстом, а не жирным. Комментария в HTML нет. Опечатка `{{ prodcut.name }}` не дала ошибки — просто пустота перед `|конец`.

`GET /empty/` выводит вместо списка `<li>Товаров пока нет.</li>` — сработал `{% empty %}`.

### Шаг 4. Метод в шаблоне
Корзина — объект с методом `total()`:

Файл `views.py`:
```python
from django.shortcuts import render


class Cart:
    def __init__(self, items):
        self.items = items

    def total(self):
        return sum(price * qty for _, price, qty in self.items)


def cart(request):
    items = [("Беспроводная мышь", 1499, 2), ("Коврик для мыши", 490, 1)]
    context = {"cart": Cart(items), "user": {"name": "Анна"}}
    return render(request, "shop/cart.html", context)
```

Файл `templates/shop/cart.html`:
```html
<p>{{ user.name }}, в корзине позиций: {{ cart.items|length }}</p>
<p>Первая: {{ cart.items.0.0 }}</p>
<p>Итого: {{ cart.total }} ₽</p>
```
Результат:
```
GET /cart/ → 200 OK

<p>Анна, в корзине позиций: 2</p>
<p>Первая: Беспроводная мышь</p>
<p>Итого: 3488 ₽</p>
```
`user.name` — ключ словаря, `cart.items.0.0` — первый элемент первой пары, `cart.total` — вызов метода без скобок. `|length` — фильтр, о них — в теме «Фильтры и свои теги».

### Шаг 5. Ошибки
Если написать `render(request, "catalog.html", …)` без папки приложения, ответ — `500` и `TemplateDoesNotExist: catalog.html`. Если в шаблоне вызвать метод со скобками `{{ cart.total() }}`, ответ — `500` и `TemplateSyntaxError: Could not parse the remainder: '()' from 'cart.total()'`.

## Частые ошибки
- **Шаблон не в подпапке приложения.** `templates/catalog.html` и `render(…, "catalog.html")` работают, пока второе приложение не принесёт свой `catalog.html`. Путь — `templates/shop/catalog.html`.
- **Скобки при вызове метода.** `{{ cart.total() }}` — `TemplateSyntaxError`. Методы вызываются без скобок; метод с аргументами из шаблона не вызвать — посчитайте во view.
- **Опечатка в переменной.** Пустая строка без ошибки. Если на странице «пропало» значение — сначала проверьте имя в контексте и в шаблоне.
- **`|safe` на данных пользователя.** Отключает экранирование — отзыв с `<script>` выполнится у каждого посетителя.
- **Логика в шаблоне.** Скидки, права, запросы к базе — во view; шаблон только выводит готовое.

## Итог
**render**
- `render(request, "shop/шаблон.html", context)` → `HttpResponse` с HTML.
- Шаблоны — в `templates/<приложение>/` внутри приложения.

**Язык шаблонов**
- `{{ x.y }}` — ключ, атрибут, метод без скобок, индекс; несуществующее — пустая строка.
- `{% if %}`, `{% for %}` с `{% empty %}` и `forloop.counter`, `{# #}` — комментарий.

**Безопасность**
- Значения в `{{ }}` экранируются автоматически; `|safe` — только для своего HTML.

## Вопросы на собеседовании
<details><summary>Что такое контекст шаблона?</summary>

Словарь данных, который view передаёт в шаблон: ключи становятся переменными шаблона. `render(request, "shop/catalog.html", {"products": products})` делает доступной `{{ products }}`. К нему добавляются переменные контекст-процессоров — например, `request` и `user`.
</details>

<details><summary>Как Django разрешает `{{ product.name }}`?</summary>

По порядку пробует: ключ словаря (`product["name"]`), атрибут или метод (`product.name`; вызываемое вызывается без аргументов), индекс списка (`product[0]` для `{{ items.0 }}`). Если ничего не подошло, подставляется пустая строка (`string_if_invalid`), ошибки нет.
</details>

<details><summary>Как шаблоны Django защищают от XSS?</summary>

Автоэкранированием: каждое значение в `{{ }}` переводится в безопасный HTML (`<` → `&lt;` и т. д.), поэтому введённый пользователем `<script>` показывается как текст. Отключают экранирование `|safe`, `{% autoescape off %}` и `mark_safe()` — только для проверенного HTML, который формирует сам сайт.
</details>

<details><summary>Почему шаблоны кладут в `templates/<имя_приложения>/`?</summary>

Загрузчик шаблонов объединяет папки `templates/` всех приложений в одно пространство имён и берёт первый найденный файл. Шаблоны с одинаковыми именами из разных приложений перекроют друг друга. Подпапка с именем приложения делает путь уникальным: `shop/catalog.html`, `blog/catalog.html`.
</details>
