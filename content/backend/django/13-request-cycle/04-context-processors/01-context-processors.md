## Теория
Шапка сайта на каждой странице показывает число товаров в корзине. Передавать `cart_count` в контекст каждого view — значит копировать одну строку в десятки мест. **Контекст-процессор** — функция, которая принимает `request` и возвращает словарь; Django добавляет его к контексту **каждого** шаблона, отрисованного с запросом:
```
def cart(request):
    cart = request.session.get("cart", {})
    return {"cart_count": sum(cart.values())}
```
Подключение — путь к функции в `TEMPLATES[0]["OPTIONS"]["context_processors"]`.

Встроенные, которые уже включены в новом проекте:
- `request` — `{{ request }}` в шаблоне (`request.path`, `request.GET`);
- `auth` — `{{ user }}` и `{{ perms }}`;
- `messages` — `{{ messages }}`;
- `debug` — `{{ debug }}` и `{{ sql_queries }}` (только при `DEBUG` и с внутренних IP).

Процессоры работают, только когда шаблон рисуется **с запросом**: `render(request, …)`, `TemplateResponse` в CBV. `render_to_string("…")` без `request=` и `Template(…).render(Context(…))` их не вызывают — переменные будут пустыми.

Процессор выполняется при **каждой** отрисовке шаблона с запросом, даже если шаблон его переменную не использует. Запрос к базе в процессоре — плюс запрос к каждой странице; держите их лёгкими, а дорогое считайте лениво или кэшируйте.

## Наглядно
**Таблица 1.** Как данные попадают в шаблон.

| Способ | Где виден | Когда использовать |
|---|---|---|
| контекст `render(request, t, {…})` | один шаблон | данные страницы |
| контекст-процессор | все шаблоны с `request` | шапка, меню, корзина, пользователь |
| свой тег `{% … %}` | где вызван | дорогие данные для одного блока |
| `render_to_string(t, ctx)` без `request` | — | процессоры **не** работают |

## На практике
Задача: в шапке каждой страницы — «Корзина: N» и число товаров в каталоге. Корзина — в сессии, как в прошлой теме. В тренажёре свои процессоры подключаются ключом `CONTEXT_PROCESSORS` в `settings` задачи (добавляются после встроенных).

### Шаг 1. Процессоры
Файл `context_processors.py`:
```python
from .models import Product


def cart(request):
    cart = request.session.get("cart", {})
    return {"cart_count": sum(cart.values())}


def catalog_size(request):
    return {"products_total": Product.objects.count()}
```
Файл `templates/shop/home.html`:
```html
<header>Корзина: {{ cart_count }} · Товаров в каталоге: {{ products_total }} · {{ user }}</header>
```
View главной — `render(request, "shop/home.html")`, без своего контекста.

### Шаг 2. Результат
После трёх добавлений в корзину:
```html
<header>Корзина: 3 · Товаров в каталоге: 3 · AnonymousUser</header>
```
Список процессоров в настройках:
```
['django.template.context_processors.request', 'django.contrib.auth.context_processors.auth', 'django.contrib.messages.context_processors.messages', 'shop.context_processors.cart', 'shop.context_processors.catalog_size']
```
Запросы к базе при открытии главной — чтение сессии и `SELECT COUNT(*)` из `catalog_size`: процессор добавил запрос к каждой странице сайта.

### Шаг 3. Без запроса
Тот же шаблон через `render_to_string("shop/home.html")` и строка `Template("Корзина: {{ cart_count }}").render(Context({}))`:
```html
<header>Корзина:  · Товаров в каталоге:  · </header>
```
Строка шаблона:
```
Корзина:
```
Процессоры не вызывались — у отрисовки нет `request`. С `render_to_string("shop/home.html", request=request)` они сработают.

## Частые ошибки
- **Рисовать без `request`.** `render_to_string` без `request=`, `Template().render(Context())` — переменные процессоров пусты.
- **Тяжёлый запрос в процессоре.** Он выполняется на каждой странице, включая ошибки 404. Лёгкие вычисления, кэш или свой тег там, где данные нужны.
- **Процессор не возвращает словарь.** `return None` или число — ошибка при отрисовке; всегда `return {…}`.
- **Одинаковые имена.** Переменная процессора и ключ контекста view с тем же именем — побеждает контекст view; называйте переменные процессоров однозначно (`cart_count`, а не `count`).
- **Логика доступа в процессоре.** Скрыть ссылку можно, но проверку прав всё равно делает view.

## Итог
**Контекст-процессор**
- `def name(request) -> dict`, путь — в `TEMPLATES[0]["OPTIONS"]["context_processors"]`.
- Добавляет переменные в каждый шаблон, отрисованный с `request`.

**Ограничения**
- Без `request` (`render_to_string` без `request=`, `Template().render`) не работает.
- Выполняется на каждой странице — без тяжёлых запросов.

## Вопросы на собеседовании
<details><summary>Что такое контекст-процессор?</summary>

Функция `(request) -> dict`, указанная в настройках шаблонного движка. При отрисовке шаблона через `RequestContext` (то есть с запросом) Django вызывает все процессоры и добавляет их словари в контекст. Пример — `auth` даёт `user` и `perms` во все шаблоны.
</details>

<details><summary>Почему переменная из контекст-процессора не видна в шаблоне?</summary>

Шаблон отрисован без запроса: `render_to_string` без `request=`, `Template().render(Context(...))`, письмо через `get_template().render({})`. Процессоры вызываются только с `RequestContext`. Ещё причина — процессор не добавлен в `context_processors` или переменную перекрыл контекст view.
</details>

<details><summary>Чем плох контекст-процессор с запросами к базе?</summary>

Он выполняется при каждой отрисовке шаблона с запросом — на всех страницах, даже где переменная не нужна. Это лишние запросы ко всему сайту. Решения: ленивое значение (функция или `SimpleLazyObject`, вычисляется при обращении в шаблоне), кэш, свой шаблонный тег только там, где данные нужны.
</details>
