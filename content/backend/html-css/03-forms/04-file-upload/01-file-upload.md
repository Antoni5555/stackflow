## Теория
Файл с компьютера покупателя отправляет поле `<input type="file">`. Но одного поля мало. Обычная форма кодирует данные как строку `a=1&b=2`, а в такой строке файлу места нет: браузер отправит только **имя** файла. Чтобы ушло содержимое, у формы должны быть `method="post"` и `enctype="multipart/form-data"`. Тогда тело запроса делится на **части**. У каждой части свои заголовки — имя поля, имя файла, тип, — а внутри лежит само содержимое, текст или байты картинки.

Атрибут `accept="image/*"` предлагает в окне выбора только картинки, `multiple` разрешает выбрать несколько файлов. Но это снова только удобство: в поле можно подсунуть что угодно, а запрос — собрать руками. Сервер проверяет тип, размер и содержимое файла сам. В Django отправленные файлы окажутся в `request.FILES`, а обычные поля той же формы — как всегда, в `request.POST`.

## Наглядно
**Таблица 1.** Что нужно для отправки файла.

| Где | Что | Без этого |
|---|---|---|
| форма | `method="post"` | GET кладёт поля в URL — файл туда не поместится |
| форма | `enctype="multipart/form-data"` | уйдёт только имя файла |
| поле | `type="file" name="photo"` | нечего отправлять |
| поле | `accept="image/*"` | в окне выбора — все файлы (это подсказка, не защита) |
| поле | `multiple` | только один файл |
| сервер | проверка типа и размера | покупатель загрузит что угодно |

**Таблица 2.** Два формата тела POST-формы.

| `enctype` | Как выглядит тело | Когда |
|---|---|---|
| `application/x-www-form-urlencoded` (по умолчанию) | `rating=5&text=…` | обычные поля |
| `multipart/form-data` | части с границами `------…`, у каждой свои заголовки | есть файлы |

## На практике
Задача: добавить к форме отзыва загрузку фото.

### Шаг 1. Готовим форму к файлам
У формы — POST и multipart, у поля — тип `file` и ограничение на картинки:
```html
<form action="/products/17/reviews/" method="post" enctype="multipart/form-data">
  <textarea name="text"></textarea>
  <label for="photo">Фото товара</label>
  <input type="file" id="photo" name="photo" accept="image/*">
  <button>Отправить</button>
</form>
```

### Шаг 2. Смотрим на тело запроса
Браузер разделил тело на части. Граница (`boundary`) указана в заголовке и придумывается браузером:
```http
POST /products/17/reviews/ HTTP/1.1
Content-Type: multipart/form-data; boundary=----b4

------b4
Content-Disposition: form-data; name="text"

Отличный чайник
------b4
Content-Disposition: form-data; name="photo"; filename="kettle.jpg"
Content-Type: image/jpeg

(байты картинки)
------b4--
```
В Django текст будет в `request.POST["text"]`, а файл — в `request.FILES["photo"]`, с именем, размером и содержимым.

### Шаг 3. Разрешаем несколько фото
Атрибут `multiple` позволяет выбрать сразу несколько файлов:
```html
<input type="file" name="photos" accept="image/*" multiple>
```
Все файлы уйдут под одним именем поля. В Django их достают списком: `request.FILES.getlist("photos")`.

### Шаг 4. Не доверяем `accept`
`accept` фильтрует только окно выбора. Покупатель может переключить «Все файлы» или собрать запрос руками и прислать `photo.exe` с заголовком `image/jpeg`. Сервер ограничивает размер и проверяет, что внутри действительно картинка: в Django для этого есть `ImageField`.

## Частые ошибки
- **Нет `enctype`.** Форма уходит, но в `request.FILES` пусто, а в `request.POST["photo"]` — только имя файла.
- **GET-форма с файлом.** Содержимое файла в URL не помещается. Файлы — только POST.
- **`accept` как проверка.** Это подсказка для окна выбора. Тип и размер проверяет сервер.
- **Без ограничения размера.** Покупатель загрузит видео на 2 ГБ. Ограничение ставят на сервере и в Nginx (`client_max_body_size`).
- **Имя файла из запроса как путь на диске.** `filename="../../settings.py"` — так можно перезаписать чужой файл. Django сохраняет файлы под безопасными именами сам.

## Итог
**Форма с файлом**
- `<form method="post" enctype="multipart/form-data">` + `<input type="file" name="…">`.
- Без `enctype` уходит только имя файла; GET файл не отправит.

**Поле файла**
- `accept="image/*"` — подсказка окну выбора; `multiple` — несколько файлов.

**Сервер**
- Django: файлы — `request.FILES`, поля — `request.POST`, несколько файлов — `getlist`.
- Тип, размер и содержимое проверяет сервер, имя файла из запроса — не путь.

## Вопросы на собеседовании
<details><summary>Зачем `enctype="multipart/form-data"`?</summary>

Формат по умолчанию (`application/x-www-form-urlencoded`) кодирует поля одной строкой `name=value&…` и не умеет передавать двоичные данные файла. `multipart/form-data` делит тело на части с собственными заголовками. Так в одном запросе идут и текстовые поля, и файлы с именами и типами.
</details>

<details><summary>Как проверить загруженный файл на сервере?</summary>

Ограничить размер (в веб-сервере и приложении), проверить реальный тип по содержимому, а не по расширению и заголовку `Content-Type`. Сохранять под сгенерированным именем вне каталога с кодом. Картинки — открыть библиотекой (Pillow, как делает `ImageField`): битый или поддельный файл не откроется.
</details>
