## Теория
Поле ввода `<input>` меняет поведение через атрибут `type`. `text` — строка, `email` — адрес (на телефоне клавиатура с «@»), `number` — число со стрелками, `password` — скрытые символы, `tel` — телефон (цифровая клавиатура), `checkbox` — галочка, `radio` — выбор одного из нескольких, `hidden` — невидимое поле со служебным значением. Для длинного текста есть `<textarea>`, для выбора из списка — `<select>` с пунктами `<option>`.

У каждого поля должна быть **подпись** `<label>`, связанная с ним: `for` у подписи совпадает с `id` у поля. Иначе экранный доступ не скажет, что это за поле, а клик по подписи не поставит курсор. У полей выбора важно различать то, что видит покупатель, и то, что уйдёт на сервер. `<option value="courier">Курьером (300 ₽)</option>` отправит `courier`. Галочка отправляется, только если отмечена. Радиокнопки одной группы обязаны иметь **одинаковый `name`** — так браузер понимает, что выбрать можно только одну.

## Наглядно
**Таблица 1.** Поля и что они отправляют.

| Поле | Разметка | Что уйдёт на сервер |
|---|---|---|
| текст | `<input name="city">` | `city=Москва` |
| email | `<input type="email" name="email">` | `email=anna@mail.ru` |
| число | `<input type="number" name="qty">` | `qty=2` (строкой) |
| телефон | `<input type="tel" name="phone">` | `phone=+79123456789` |
| пароль | `<input type="password" name="password">` | `password=…` — открытым текстом, нужен HTTPS |
| галочка | `<input type="checkbox" name="gift" value="1">` | `gift=1`, а если не отмечена — **ничего** |
| радиокнопки | три `<input type="radio" name="delivery" value="…">` | одно значение: `delivery=pickup` |
| список | `<select name="delivery"><option value="courier">…` | `value` выбранного пункта |
| многострочный текст | `<textarea name="comment">` | `comment=…` |
| скрытое | `<input type="hidden" name="product_id" value="17">` | `product_id=17` |

## На практике
Задача: сверстать форму оформления заказа.

### Шаг 1. Подписываем поля
Подпись связывается с полем через `for` и `id`:
```html
<label for="email">Email</label>
<input type="email" id="email" name="email">
```
Другой способ — вложить поле в подпись, тогда `for` не нужен:
```html
<label>Телефон <input type="tel" name="phone"></label>
```
Клик по слову «Email» ставит курсор в поле, а экранный доступ читает «Email, поле ввода».

### Шаг 2. Делаем выбор доставки
Радиокнопки одной группы — с общим `name` и разными `value`:
```html
<label><input type="radio" name="delivery" value="courier"> Курьером</label>
<label><input type="radio" name="delivery" value="pickup" checked> Самовывоз</label>
<label><input type="radio" name="delivery" value="post"> Почтой</label>
```
`checked` отмечает вариант по умолчанию. Если бы у кнопок были разные `name`, покупатель мог бы отметить все три сразу.

### Шаг 3. Добавляем галочку и комментарий
Галочка «Подарочная упаковка» и поле комментария:
```html
<label><input type="checkbox" name="gift" value="1"> Подарочная упаковка</label>
<label for="comment">Комментарий курьеру</label>
<textarea id="comment" name="comment" rows="3"></textarea>
```
Если галочка не отмечена, поля `gift` в запросе не будет совсем. Поэтому на сервере проверяют «есть ли ключ», а не «равен ли он 0».

### Шаг 4. Смотрим, что уйдёт на сервер
Покупатель выбрал самовывоз и не отметил упаковку. Соберём тело запроса так же, как браузер:
```python
from urllib.parse import urlencode

fields = {"email": "anna@mail.ru", "delivery": "pickup", "comment": ""}
print(urlencode(fields))
```
Результат:
```
email=anna%40mail.ru&delivery=pickup&comment=
```
Пустой комментарий ушёл пустой строкой, а неотмеченной галочки в запросе нет вовсе. `@` закодирован как `%40`.

## Частые ошибки
- **Подпись без связи.** `<label>Email</label><input id="email">` — подпись просто стоит рядом. Нужен `for="email"` или вложенное поле.
- **Разные `name` у радиокнопок.** Каждая кнопка становится отдельной группой, и выбрать можно все.
- **`option` без `value`.** Отправится видимый текст «Курьером (300 ₽)», и сервер будет разбирать подписи. Цена в подписи поменяется — и код сломается.
- **Галочка «0/1».** Неотмеченная галочка ничего не отправляет: `request.POST.get("gift")` вернёт `None`, а не `"0"`.
- **`placeholder` вместо подписи.** Подсказка внутри поля исчезает при вводе, и экранный доступ её часто не читает. Подпись — `label`.
- **Пароль — значит, защищён.** `type="password"` лишь скрывает символы на экране. В запросе пароль идёт открытым текстом — защищает только HTTPS.

## Итог
**Поля**
- `input` с `type`: `text`, `email`, `number`, `tel`, `password`, `checkbox`, `radio`, `hidden`; плюс `textarea` и `select`/`option`.
- Тип поля влияет на клавиатуру телефона и встроенную проверку браузера.

**Подписи**
- `<label for="id">` + `<input id="id">` или поле внутри `label`.
- `placeholder` — не подпись.

**Что отправляется**
- Радиокнопки одной группы — один `name`, уходит `value` выбранной.
- `option` — уходит `value`, а не видимый текст.
- Неотмеченная галочка не отправляется совсем.

## Вопросы на собеседовании
<details><summary>Зачем связывать `label` с полем?</summary>

Подпись становится «именем» поля для экранного доступа, а клик по ней фокусирует поле или переключает галочку. Для маленьких галочек и радиокнопок это заметно упрощает попадание пальцем. Связь — через `for` и `id` или вложением поля в `label`.
</details>

<details><summary>Чем checkbox отличается от radio?</summary>

Галочки независимы: можно отметить любое число, каждая отправляется своим `name` (или одним `name` с несколькими значениями). Радиокнопки с одинаковым `name` образуют группу, и выбрать можно только одну — отправится её `value`.
</details>

<details><summary>Что отправляет неотмеченный checkbox?</summary>

Ничего: ключа нет в данных формы. На сервере это проверяют как «ключ отсутствует». В Django `BooleanField` формы обрабатывает это сам и даёт `False`.
</details>
