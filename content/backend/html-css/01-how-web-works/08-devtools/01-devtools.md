## Теория
Всё, о чём шла речь в разделе, — запросы, заголовки, коды, cookies — можно увидеть своими глазами. Для этого в каждом браузере есть **инструменты разработчика** (DevTools), открываются клавишей F12 или `Ctrl+Shift+I` (на Mac — `Cmd+Option+I`). Для backend-разработчика главная вкладка — **Network** (Сеть). В ней каждая строка — один запрос страницы, с методом, адресом, кодом ответа, размером и временем.

Network — первый инструмент, когда «что-то не работает». Картинка не загрузилась — ищем красную строку с 404. Форма «ничего не делает» — смотрим, ушёл ли POST и что вернул сервер. Вход «не держится» — проверяем, пришёл ли `Set-Cookie`. Вкладка **Application** (Приложение) показывает cookies сайта, а **Elements** — HTML страницы, каким его видит браузер.

## Наглядно
**Таблица 1.** Что смотреть во вкладке Network.

| Где | Что показывает | Зачем backend-разработчику |
|---|---|---|
| колонка **Status** | код ответа | красные 4xx/5xx — первые подозреваемые |
| колонка **Type** | `document`, `stylesheet`, `fetch`, `img` | отличить страницу от стилей и запросов JS |
| **Headers** (по клику на строку) | URL, метод, код, заголовки запроса и ответа | `Location`, `Set-Cookie`, `Content-Type` |
| **Payload** | query-параметры и тело запроса | что именно отправила форма |
| **Response** / **Preview** | тело ответа | HTML ошибки, JSON от API |
| **Cookies** | cookies запроса и ответа | ушла ли `sessionid`, пришла ли новая |
| фильтр и кнопки «All / Doc / CSS / Img» | отбор строк | найти нужный запрос среди сотни |
| флажок **Preserve log** | не очищать список при переходе | увидеть POST перед редиректом |
| флажок **Disable cache** | грузить всё заново | проверить свежий CSS, а не копию из кэша |

**Таблица 2.** Другие вкладки, которые пригодятся.

| Вкладка | Что в ней |
|---|---|
| Elements | дерево HTML и стили выбранного элемента |
| Console | ошибки JavaScript и сообщения браузера (например, о mixed content) |
| Application | cookies, localStorage — можно посмотреть и удалить |

## На практике
Задача: на карточке товара не показывается фото. Найти, какой запрос вернул 404, и понять, почему.

### Шаг 1. Открываем Network и перезагружаем страницу
DevTools показывает только запросы, сделанные, пока панель открыта. Открываем F12 → Network и обновляем страницу. Список заполняется: первая строка — сам HTML (`document`), дальше стили, скрипты и картинки.

### Шаг 2. Ищем красную строку
Кликаем фильтр **Img** и смотрим на колонку Status. Одна строка красная:
```text
Name               Status   Type   Size
kettle-steel.jpg   404      jpeg   1.2 kB
logo.svg           200      svg+xml 3.4 kB
```
Фото запрошено, но сервер его не нашёл.

### Шаг 3. Смотрим полный адрес запроса
Кликаем по строке → **Headers**:
```http
Request URL: https://shop.example/products/17/img/kettle-steel.jpg
Request Method: GET
Status Code: 404 Not Found
```
Картинку ищут внутри `/products/17/`, а лежит она в `/static/img/`. В HTML путь записан относительно: `src="img/kettle-steel.jpg"`. Браузер достроил его от адреса текущей страницы. Нужен путь от корня сайта: `src="/static/img/kettle-steel.jpg"`. Абсолютные и относительные пути — тема раздела «HTML».

### Шаг 4. Ловим запрос перед редиректом
Отдельная задача: форма отзыва после отправки возвращает на карточку, но отзыв не появляется. В Network видна только последняя загрузка карточки — POST пропал из списка при переходе. Включаем **Preserve log** и отправляем форму ещё раз:
```text
Name        Method   Status
reviews/    POST     302
17/         GET      200
```
POST ушёл и получил редирект — сервер принял форму. Открываем у POST вкладку **Payload** и смотрим, какие поля отправились. Если `text` пустой — проблема в форме, а не на сервере.

## Частые ошибки
- **Открыть Network после загрузки.** Запросы, сделанные до открытия панели, не видны. Открыли — обновите страницу.
- **Потерять POST при редиректе.** Без Preserve log список очищается при переходе на новую страницу, и виден только итоговый GET.
- **Смотреть на старый CSS.** Браузер взял файл из кэша (в Size написано `disk cache` или `memory cache`). Включите Disable cache на время разработки или обновите страницу с `Ctrl+Shift+R`.
- **Исправлять «в DevTools».** Правки в Elements и Styles живут до перезагрузки. Это способ попробовать, а исправлять нужно файлы проекта.
- **Доверять тому, что видно в Elements.** Elements показывает DOM после работы браузера и скриптов. Что прислал сервер, видно в Network → Response.

## Итог
**Открыть**
- F12 или `Ctrl+Shift+I`, вкладка Network; открыть до загрузки страницы или обновить.

**Найти запрос**
- Фильтры All / Doc / CSS / Img и строка поиска; красные строки — 4xx/5xx.
- Preserve log — не терять запросы при переходах (POST перед редиректом).
- Disable cache — видеть свежие файлы.

**Разобрать запрос**
- Headers — URL, метод, код, заголовки (`Location`, `Set-Cookie`).
- Payload — что отправлено, Response — что вернулось, Cookies — какие cookies ушли и пришли.

**Другие вкладки**
- Application — cookies сайта, Console — ошибки браузера, Elements — текущий HTML.

## Вопросы на собеседовании
<details><summary>Как найти, почему на странице не загружается картинка или стиль?</summary>

Открыть DevTools → Network, обновить страницу и найти запрос этого файла. Если код 404 — смотреть полный Request URL: обычно неверный путь (относительный вместо абсолютного) или файл не попал в статику. Если 403 или 500 — проблема на сервере, нужен его лог.
</details>

<details><summary>Как проверить, что сервер поставил cookie?</summary>

В Network выбрать ответ, после которого cookie должна появиться, и посмотреть заголовок `Set-Cookie` во вкладке Headers или Cookies. Затем в Application → Cookies убедиться, что браузер её сохранил. Если заголовок есть, а cookie нет — браузер её отверг: например, `Secure` на HTTP или не тот домен.
</details>

<details><summary>Чем Elements отличается от «Просмотра кода страницы»?</summary>

«Просмотр кода» (`Ctrl+U`) показывает HTML ровно таким, каким его прислал сервер. Elements показывает текущее дерево DOM: после исправления ошибок разметки браузером и после изменений JavaScript. Для проверки шаблона Django смотрят исходный HTML или Network → Response.
</details>
