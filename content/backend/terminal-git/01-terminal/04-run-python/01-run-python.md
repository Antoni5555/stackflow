## Теория
В курсе Python код запускался в тренажёре. На своём компьютере и на сервере скрипт запускают из терминала:
```bash
python3 export_orders.py
```
В Ubuntu и других Linux команда — **`python3`**: просто `python` по умолчанию нет (`Command 'python' not found`), пока не установлен пакет `python-is-python3` или не включено виртуальное окружение (следующая тема). В Windows обычно `python` или `py`. Какая версия — `python3 --version`.

Путь к скрипту — обычный путь из прошлой темы: от текущей папки (`python3 scripts/export.py`) или абсолютный. Не та папка — `can't open file '…': [Errno 2] No such file or directory`.

**Аргументы.** Всё, что написано после имени скрипта, Python кладёт в список **`sys.argv`**: `sys.argv[0]` — имя скрипта, дальше — аргументы по порядку, **всегда строками**. `python3 export_orders.py 2026-04-15 --format csv` даст `['export_orders.py', '2026-04-15', '--format', 'csv']`. Аргумент с пробелом — в кавычках. Для настоящих консольных утилит с флагами и справкой есть модуль `argparse`, но в основе — тот же `sys.argv`.

**Код выхода скрипта.** Скрипт, который дошёл до конца, возвращает `0`; необработанное исключение — `1`; `sys.exit(код)` завершает его с нужным кодом. Хороший скрипт при ошибке пишет сообщение в поток ошибок (`print(…, file=sys.stderr)`) и выходит с ненулевым кодом — тогда `&&`, cron и CI понимают, что что-то пошло не так.

**`python3 -m модуль`** запускает модуль как программу — по имени, а не по пути к файлу. Так запускают инструменты, которые поставляются вместе с Python или пакетами: `python3 -m venv venv` (создать окружение), `python3 -m pip install …`, `python3 -m pytest`, `python3 -m json.tool` (красиво отформатировать JSON). Так гарантировано, что инструмент работает с тем же Python, которым вы его вызвали.

В тренажёре этого курса Python не выполняется — вывод ниже снят на Ubuntu 24.04 с Python 3.12. Код скриптов можно запускать в тренажёре Python.

## На практике
Задача: скрипт выгрузки заказов за день, дата — аргументом из командной строки.

### Шаг 1. Скрипт
Файл `export_orders.py`:
```python
import sys

print("Аргументы:", sys.argv)
if len(sys.argv) < 2:
    print("Укажите дату: python3 export_orders.py 2026-04-15", file=sys.stderr)
    sys.exit(1)
print(f"Выгрузка заказов за {sys.argv[1]}")
```

### Шаг 2. Запуск без аргумента
Запускаем, забыв дату, и смотрим код выхода:
```bash
python3 export_orders.py
echo $?
```
Результат:
```
Аргументы: ['export_orders.py']
Укажите дату: python3 export_orders.py 2026-04-15
1
```
Аргументов нет — только имя скрипта. Скрипт объяснил, чего не хватает, и вышел с кодом `1`.

### Шаг 3. С аргументами
Дата и ещё два аргумента:
```bash
python3 export_orders.py 2026-04-15 --format csv
echo $?
```
Результат:
```
Аргументы: ['export_orders.py', '2026-04-15', '--format', 'csv']
Выгрузка заказов за 2026-04-15
0
```
`--format` и `csv` — два отдельных элемента списка: разбирать флаги — забота скрипта (или `argparse`).

### Шаг 4. Ошибка в коде
Если скрипт упал с исключением, код выхода — `1`. Файл `broken.py`:
```python
total = 100
print(total / 0)
```
Запуск:
```bash
python3 broken.py
echo $?
```
Результат:
```
Traceback (most recent call last):
  File "/home/shop/shop/broken.py", line 2, in <module>
    print(total / 0)
          ~~~~~~^~~
ZeroDivisionError: division by zero
1
```

### Шаг 5. Модуль по имени
`json.tool` из стандартной библиотеки форматирует JSON:
```bash
echo '{"id": 33, "status": "new"}' | python3 -m json.tool
```
Результат:
```
{
    "id": 33,
    "status": "new"
}
```

## Частые ошибки
- **`python` вместо `python3` в Linux.** `Command 'python' not found` — пишите `python3` (или активируйте окружение).
- **Запуск не из той папки.** `can't open file … No such file or directory` — проверьте `pwd` и путь к скрипту.
- **Аргументы — не строки.** `sys.argv[1]` всегда `str`; число нужно преобразовать `int(…)`.
- **Ошибка без ненулевого кода.** `print("Ошибка")` и обычный выход — для `&&` и cron это успех; нужен `sys.exit(1)`.
- **`pip install` без `python3 -m`.** На машине с несколькими Python `pip` может поставить пакет не туда; `python3 -m pip` — в тот, который вызываете.

## Итог
**Запуск**
- `python3 путь/к/скрипту.py`; в Linux — `python3`, не `python`.
- `python3 -m модуль` — запуск модуля по имени.

**Аргументы и код выхода**
- `sys.argv` — список строк, `[0]` — имя скрипта.
- Успех — `0`, исключение — `1`, `sys.exit(код)` — свой код; сообщение об ошибке — в `stderr`.

## Вопросы на собеседовании
<details><summary>Что содержит `sys.argv`?</summary>

Список строк — аргументы командной строки: нулевой элемент — путь к скрипту в том виде, как его указали при запуске, дальше — аргументы по порядку. Типы не преобразуются, кавычки оболочка убирает, а аргумент в кавычках с пробелами приходит одним элементом.
</details>

<details><summary>Зачем писать `python3 -m pip`, а не просто `pip`?</summary>

`python3 -m pip` гарантированно использует pip того интерпретатора, который вы вызвали, — пакеты попадут именно в его окружение. Команда `pip` берётся из `PATH` и на машине с несколькими версиями Python или окружениями может оказаться чужой.
</details>

<details><summary>Как скрипт сообщает об ошибке вызывающей программе?</summary>

Ненулевым кодом выхода (`sys.exit(1)` или необработанное исключение) и сообщением в поток ошибок `stderr`. Оболочка, cron, CI и другие программы смотрят на код выхода; `stderr` можно перенаправить отдельно от обычного вывода (`2>`).
</details>
