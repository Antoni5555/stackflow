## Теория
Встроенные функции PostgreSQL вызывают прямо в запросе — в `SELECT`, `WHERE`, `ORDER BY`. Они считаются для каждой строки.

**Строки:** `lower(s)`, `upper(s)` — регистр; `length(s)` — длина; `trim(s)` — убрать пробелы по краям; `substring(s from 1 for 3)` — кусок строки; `replace(s, 'a', 'b')`; склейка — оператор `||` или функция `concat(…)`, которая, в отличие от `||`, пропускает NULL.

**Числа:** `round(x)` — до целого, `round(x, 2)` — до двух знаков; `abs(x)`; `ceil(x)`, `floor(x)` — вверх и вниз. Важная ловушка — **целочисленное деление**: если оба числа целые, результат тоже целый, дробная часть отбрасывается. `7 / 2` — это `3`, а `10 / 100` — `0`. Чтобы получить дробь, хотя бы одно число должно быть дробным: `7 / 2.0` или `7::numeric / 2`.

**Приведение типов**: `CAST(x AS тип)` или короче `x::тип` (запись PostgreSQL). `'2026-04-15'::date`, `created_at::date` — дата без времени, `price::integer` — целое.

**Даты и время**: `now()` — текущий момент (в учебных задачах его не используют: ответ зависел бы от дня запуска); `date_trunc('month', created_at)` — обрезать до начала месяца; `extract(year from created_at)` — часть даты; `interval '7 days'` — промежуток, который прибавляют к дате и вычитают из неё. Сравнивать `timestamptz` с датой нужно аккуратно: `created_at = '2026-04-15'` ищет ровно полночь. Нужен день — приводят к дате (`created_at::date = '2026-04-15'`) или берут интервал `>= день AND < следующий день`.

**`CASE`** — условие внутри выражения, как `if/elif/else`:
```sql
CASE
    WHEN stock = 0 THEN 'нет в наличии'
    WHEN stock < 5 THEN 'мало'
    ELSE 'есть'
END
```
Ветки проверяются по порядку, срабатывает первая подходящая. Если не подошла ни одна, а `ELSE` нет, результат — NULL. Короткая форма `CASE status WHEN 'new' THEN … END` сравнивает одно значение с вариантами.

**Таблица 1.** Часто используемые функции.

| Функция | Пример | Результат |
|---|---|---|
| `upper(s)` | `upper('welcome10')` | `WELCOME10` |
| `length(s)` | `length('VIP15')` | `5` |

## На практике
Задача: витрина ноутбуков с ценой по акции и наличием, заказы с русскими статусами и заказы за последнюю неделю.

### Шаг 1. Округление и CASE
Цена со скидкой 15 % до целых рублей и наличие словами:
```sql
SELECT name, price,
       round(price * 0.85) AS sale_price,
       CASE
           WHEN stock = 0 THEN 'нет в наличии'
           WHEN stock < 5 THEN 'мало'
           ELSE 'есть'
       END AS availability
FROM products
WHERE category_id = 3;
```
Результат:
```
         name         |  price   | sale_price | availability
----------------------+----------+------------+---------------
 Ноутбук Aster 14     | 64990.00 |      55242 | есть
 Ноутбук Aster 16 Pro | 89990.00 |      76492 | мало
 Ноутбук Nimbus Air   | 54990.00 |      46742 | нет в наличии
(3 rows)
```
Порядок веток важен: если поставить `stock < 5` первым, товар с нулевым остатком получит «мало».

### Шаг 2. Статус по-русски
Короткая форма `CASE` — одно значение против вариантов:
```sql
SELECT id, status,
       CASE status
           WHEN 'new' THEN 'новый'
           WHEN 'paid' THEN 'оплачен'
           WHEN 'shipped' THEN 'отправлен'
           ELSE 'отменён'
       END AS status_ru
FROM orders
WHERE user_id = 2;
```
Результат:
```
 id |  status   | status_ru
----+-----------+-----------
  2 | shipped   | отправлен
  9 | cancelled | отменён
 16 | shipped   | отправлен
 25 | shipped   | отправлен
 33 | new       | новый
(5 rows)
```

### Шаг 3. Заказы за неделю
Неделя до 15 апреля 2026 включительно — семь дней, считая 15-е. Дату пишем строкой: учебные данные не меняются со временем:
```sql
SELECT id, created_at
FROM orders
WHERE created_at >= '2026-04-15'::date - interval '6 days'
  AND created_at < '2026-04-16';
```
Результат:
```
 id |       created_at
----+------------------------
 30 | 2026-04-09 19:05:00+03
 31 | 2026-04-12 10:20:00+03
 32 | 2026-04-14 16:45:00+03
 33 | 2026-04-15 11:30:00+03
 34 | 2026-04-15 20:10:00+03
(5 rows)
```
В живом приложении вместо даты стоял бы `now()`: `created_at >= now() - interval '7 days'`.

### Шаг 4. Начало месяца
`date_trunc` группирует заказы по месяцам — пригодится в разделе про агрегацию:
```sql
SELECT id, created_at, date_trunc('month', created_at) AS month
FROM orders
WHERE id IN (4, 5);
```
Результат:
```
 id |       created_at       |         month
----+------------------------+------------------------
  4 | 2025-11-30 23:50:00+03 | 2025-11-01 00:00:00+03
  5 | 2025-12-01 00:10:00+03 | 2025-12-01 00:00:00+03
(2 rows)
```
Заказы с разницей в 20 минут попали в разные месяцы: часовой пояс базы — московский, и полночь считается по Москве.

## Частые ошибки
- **Целочисленное деление.** `discount_percent / 100` для скидки 10 % — `0`. Нужно `discount_percent / 100.0`.
- **`CASE` без `ELSE`.** Неучтённое значение превращается в NULL.
- **Неверный порядок веток.** Срабатывает первая подходящая ветка — частные случаи ставят раньше общих.
- **`timestamptz = 'дата'`.** Совпадает только полночь. День — через `::date` или интервал.
- **`now()` в отчёте с фиксированным периодом.** Результат меняется каждый день. Для «отчёта за март» — даты строкой.

## Итог
**Функции**
- Строки: `lower`, `upper`, `length`, `trim`, `substring`, `replace`, `||`, `concat`.
- Числа: `round`, `abs`, `ceil`, `floor`; целое `/` целое — целое.
- Типы: `CAST(x AS тип)` и `x::тип`.
- Даты: `now()`, `date_trunc`, `extract`, `interval`; день из `timestamptz` — `::date`.

**CASE**
- `CASE WHEN … THEN … ELSE … END` — ветки по порядку, первая подходящая.
- Без `ELSE` — NULL для неучтённых значений.
- Короткая форма: `CASE столбец WHEN значение THEN … END`.

## Вопросы на собеседовании
<details><summary>Почему `SELECT 10 / 100` возвращает 0?</summary>

Оба операнда целые, и PostgreSQL выполняет целочисленное деление, отбрасывая дробную часть. Чтобы получить `0.1`, один из операндов делают дробным: `10 / 100.0` или `10::numeric / 100`.
</details>

<details><summary>Что вернёт `CASE`, если ни одно условие не подошло?</summary>

Значение из `ELSE`, а если `ELSE` нет — NULL. Ветки проверяются по порядку, и выполняется только первая подходящая.
</details>

<details><summary>Чем `timestamp` отличается от `timestamptz`?</summary>

`timestamptz` хранит момент времени (внутри — в UTC) и показывает его в часовом поясе сессии. `timestamp` хранит «часы на стене» без пояса, и одно и то же значение в разных поясах означает разные моменты. Для событий — заказов, регистраций — берут `timestamptz`.
</details>
