## Теория
`SELECT DISTINCT` убирает из результата повторяющиеся строки: из нескольких одинаковых остаётся одна. `SELECT DISTINCT city FROM users` — список городов, где каждый город один раз, сколько бы покупателей там ни жило.

`DISTINCT` относится **ко всей строке результата**, а не к первому столбцу. `SELECT DISTINCT user_id, status` оставляет уникальные **пары** «покупатель — статус»: у покупателя с заказами в трёх статусах будет три строки. Запись `DISTINCT(user_id), status` выглядит как функция, но скобки здесь просто окружают столбец — результат тот же, уникальные пары.

NULL для `DISTINCT` считаются одинаковыми: несколько покупателей без города дадут одну строку с NULL. Обычно её убирают условием `WHERE city IS NOT NULL`.

`DISTINCT` — не способ «починить» дубли. Если после соединения таблиц строки неожиданно повторяются, причина в запросе, и `DISTINCT` её только спрячет. Он нужен, когда вопрос и правда про уникальные значения: «в каких городах», «какие покупатели делали заказы».

## Наглядно
**Таблица 1.** Что именно уникально.

| Запрос | Уникально |
|---|---|
| `SELECT DISTINCT city FROM users` | города |
| `SELECT DISTINCT user_id, status FROM orders` | пары покупатель — статус |
| `SELECT DISTINCT(user_id), status FROM orders` | тоже пары — скобки ничего не меняют |
| `SELECT DISTINCT user_id FROM orders` | покупатели, у которых есть заказы |

## На практике
Задача: в каких городах есть покупатели и в каких статусах бывают заказы у двух покупателей.

### Шаг 1. Уникальные города
Города без повторов и без NULL, по алфавиту:
```sql
SELECT DISTINCT city
FROM users
WHERE city IS NOT NULL
ORDER BY city;
```
Результат:
```
      city
-----------------
 Екатеринбург
 Казань
 Краснодар
 Москва
 Новосибирск
 Санкт-Петербург
(6 rows)
```
Покупателей 13, городов 6: Москва встречается четыре раза, Казань и Петербург — по два.

### Шаг 2. Уникальные пары
Какие статусы заказов встречаются у покупателей 2 и 3:
```sql
SELECT DISTINCT user_id, status
FROM orders
WHERE user_id IN (2, 3)
ORDER BY user_id, status;
```
Результат:
```
 user_id |  status
---------+-----------
       2 | cancelled
       2 | new
       2 | shipped
       3 | cancelled
       3 | paid
       3 | shipped
(6 rows)
```
`user_id` повторяется: уникальна пара целиком. У покупателя 2 три отправленных заказа, а строка `shipped` — одна.

## Частые ошибки
- **`DISTINCT` для одного столбца из нескольких.** Уникальна вся строка. Нужны уникальные покупатели — в `SELECT` оставляют только `user_id`.
- **`DISTINCT(col)` как функция.** Скобки не превращают `DISTINCT` в функцию одного столбца.
- **Лишняя строка с NULL.** Все NULL схлопываются в одну строку; если она не нужна — `WHERE … IS NOT NULL`.
- **Прятать дубли от ошибочного запроса.** Если строки повторяются после соединения таблиц, ищут ошибку в соединении, а не добавляют `DISTINCT`.

## Итог
**DISTINCT**
- Убирает повторяющиеся строки результата целиком.
- Несколько столбцов — уникальные комбинации.
- Все NULL считаются одинаковыми и дают одну строку.
- Нужен для вопросов про уникальные значения, а не для маскировки дублей.

## Вопросы на собеседовании
<details><summary>Что вернёт `SELECT DISTINCT a, b`?</summary>

Уникальные комбинации `(a, b)`. Значения `a` при этом могут повторяться — с разными `b`.
</details>

<details><summary>Как `DISTINCT` относится к NULL?</summary>

Для `DISTINCT` (и для `GROUP BY`) NULL равны друг другу, поэтому все строки с NULL в столбце дают одну строку результата — в отличие от сравнения `NULL = NULL`, которое даёт NULL.
</details>

<details><summary>Что такое `DISTINCT ON` в PostgreSQL?</summary>

Расширение PostgreSQL: `SELECT DISTINCT ON (user_id) user_id, id, created_at FROM orders ORDER BY user_id, created_at DESC` оставляет по одной строке на каждого `user_id` — первую по порядку `ORDER BY`, здесь последний заказ покупателя. В стандартном SQL ту же задачу решают оконной функцией `ROW_NUMBER`.
</details>
