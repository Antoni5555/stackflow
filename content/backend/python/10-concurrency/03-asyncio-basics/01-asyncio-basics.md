## Теория
В первой теме три запроса через `asyncio` заняли время самого медленного, а не сумму. Чтобы так писать самому, нужно понять четыре вещи: корутину, `await`, цикл событий и `asyncio.run`.

**Корутина** — функция, объявленная через `async def`. Главное отличие от обычной: **вызов не выполняет её тело**, а возвращает объект корутины — «заготовку», которую ещё надо запустить. `check_stock(1)` — это не остаток, а обещание его посчитать.

**`await`** — «запусти и дождись результата». `stock = await check_stock(1)` выполняет корутину и кладёт её результат в переменную. Пока корутина ждёт (сеть, таймер), `await` **отдаёт управление** циклу событий. Писать `await` можно только внутри `async def`.

**Цикл событий** (event loop) — диспетчер, который выполняет корутины в одном потоке. У него список готовых к работе задач: он запускает одну до ближайшего `await` с ожиданием, потом следующую, а когда ожидание закончилось (пришёл ответ, истёк таймер) — продолжает ту, что ждала.

**`asyncio.run(main())`** — точка входа: создаёт цикл событий, выполняет корутину `main` до конца, закрывает цикл и возвращает результат. В программе его вызывают один раз, снаружи всех корутин.

Два важных следствия:
- `await` одной корутины за другой — это **по очереди**, как обычные вызовы. Одновременность появляется, только когда в цикле несколько задач (`gather`, `create_task` — следующая тема);
- ждать в корутине можно только «асинхронно»: `await asyncio.sleep(1)` отдаёт управление циклу, а `time.sleep(1)` усыпляет весь поток — и все корутины стоят.

То, что можно поставить после `await`, называют **awaitable**: корутины, задачи (`Task`) и низкоуровневые `Future`.

**Таблица 1.** Синтаксис asyncio.

| Что | Как | Что получится |
|---|---|---|
| объявить корутину | `async def check_stock(id):` | функция-корутина |
| вызвать без `await` | `c = check_stock(1)` | объект корутины, тело не выполнялось |
| выполнить и дождаться | `stock = await check_stock(1)` | результат; только внутри `async def` |
| асинхронная пауза | `await asyncio.sleep(0.1)` | ждёт, не блокируя другие корутины |
| запустить программу | `asyncio.run(main())` | цикл событий, результат `main` |

**Таблица 2.** Обычная функция и корутина.

| | `def` | `async def` |
|---|---|---|
| вызов `f()` | выполняет тело | возвращает объект корутины |
| получить результат | `x = f()` | `x = await f()` или `asyncio.run(f())` |
| ожидание | `time.sleep` — блокирует поток | `await asyncio.sleep` — отдаёт управление |
| откуда вызывать | откуда угодно | `await` — из корутины, `asyncio.run` — из обычного кода |

## На практике
Задача: написать асинхронную проверку склада и оплату, запустить их и увидеть, чем `await` отличается от обычного вызова. Сервисы имитируем через `asyncio.sleep`.

### Шаг 1. Вызов корутины ничего не выполняет
Корутина печатает, когда начинает работу:
```python
import asyncio
import time

STOCK = {1: 3, 2: 0}


async def check_stock(product_id):
    print("склад: проверяю", product_id)
    await asyncio.sleep(0.1)
    return STOCK[product_id]


c = check_stock(1)
print(type(c).__name__)
c.close()
```
Результат:
```
coroutine
```
«склад: проверяю» не напечаталось: вызов только создал объект корутины. `c.close()` — выбросить заготовку; без этого Python при удалении объекта предупредит `RuntimeWarning: coroutine 'check_stock' was never awaited` — подсказка, что забыли `await`.

### Шаг 2. asyncio.run — точка входа
Запускаем корутину из обычного кода:
```python
print(asyncio.run(check_stock(1)))
```
Результат:
```
склад: проверяю 1
3
```
`asyncio.run` создал цикл событий, выполнил корутину до конца и вернул её результат.

### Шаг 3. await — дождаться результата
Оформление заказа: проверить склад, потом оплатить. `main` — корутина, которая вызывает другие через `await`:
```python
async def pay(amount):
    print("банк: списываю", amount)
    await asyncio.sleep(0.2)
    return "pay_42"


async def main():
    stock = await check_stock(1)
    if stock == 0:
        return "нет в наличии"
    return await pay(2490)


start = time.perf_counter()
print(asyncio.run(main()))
print(round(time.perf_counter() - start, 1))
```
Результат:
```
склад: проверяю 1
банк: списываю 2490
pay_42
0.3
```
Шаги шли по очереди — 0,1 + 0,2. Здесь так и нужно: платить имеет смысл только после проверки склада. Сам по себе `await` не делает код параллельным.

### Шаг 4. await вне корутины
`await` в обычном коде — ошибка ещё до запуска:
```python
stock = await check_stock(1)
```
Результат:
```
  File "main.py", line 1
    stock = await check_stock(1)
            ^^^^^^^^^^^^^^^^^^^^
SyntaxError: 'await' outside function
```
Из обычного кода корутину запускают через `asyncio.run`, а `await` пишут внутри `async def`.

### Шаг 5. time.sleep останавливает всех
Две проверки склада одновременно (`gather` из темы 01). В одной ждём правильно, в другой — `time.sleep`:
```python
async def good(name):
    await asyncio.sleep(0.1)
    return name


async def bad(name):
    time.sleep(0.1)
    return name


async def run_two(f):
    start = time.perf_counter()
    await asyncio.gather(f("склад 1"), f("склад 2"))
    return round(time.perf_counter() - start, 1)


print("asyncio.sleep:", asyncio.run(run_two(good)))
print("time.sleep:", asyncio.run(run_two(bad)))
```
Результат:
```
asyncio.sleep: 0.1
time.sleep: 0.2
```
`time.sleep` не отдаёт управление: пока первая корутина спит, цикл событий не может запустить вторую. Так же ведут себя любые блокирующие вызовы — `requests.get`, синхронный драйвер базы (тема 07).

## Частые ошибки
- **Забыть `await`.** `stock = check_stock(1)` — в `stock` объект корутины, а не число; сравнение `stock > 0` упадёт с `TypeError`, а Python предупредит `coroutine … was never awaited`.
- **`await` вне `async def`.** `SyntaxError: 'await' outside function`. Из обычного кода — `asyncio.run(...)`.
- **`time.sleep` в корутине.** Блокирует весь цикл событий. Внутри `async def` — только `await asyncio.sleep`.
- **Ждать ускорения от `await` подряд.** `await a(); await b()` — по очереди, как обычные вызовы. Одновременно — `gather` или задачи (следующая тема).
- **`asyncio.run` внутри корутины.** Цикл уже работает: `RuntimeError: asyncio.run() cannot be called from a running event loop`. Внутри корутин — только `await`.
- **`asyncio.run` на каждый вызов.** Каждый раз — новый цикл событий; общие задачи и соединения между ними не живут. Один `asyncio.run(main())` на программу, остальное — корутины.

## Итог
**Корутина**
- `async def` — вызов возвращает объект корутины, тело не выполняется.
- Результат — через `await` (внутри корутины) или `asyncio.run` (снаружи).

**Цикл событий**
- Выполняет корутины в одном потоке; переключается на `await`, когда корутина ждёт.
- `asyncio.run(main())` — одна точка входа на программу.

**Ожидание**
- `await asyncio.sleep`, асинхронные библиотеки — отдают управление.
- `time.sleep` и блокирующие вызовы останавливают все корутины.

## Вопросы на собеседовании
<details><summary>Что такое корутина и чем она отличается от обычной функции?</summary>

Функция, объявленная через `async def`. Её вызов не выполняет тело, а возвращает объект корутины. Выполняет её цикл событий — через `await` или `asyncio.run`. Корутина может приостановиться на `await` и продолжить работу позже с того же места, отдав управление другим корутинам.
</details>

<details><summary>Что делает event loop?</summary>

Управляет выполнением корутин в одном потоке: держит очередь готовых задач, запускает каждую до ближайшего ожидания, следит за таймерами и вводом-выводом и возобновляет корутину, когда её ожидание завершилось. Переключение происходит только на `await`, поэтому корутина, которая долго считает без `await`, останавливает всех.
</details>

<details><summary>Что такое awaitable-объекты?</summary>

То, что можно поставить после `await`: корутины, задачи (`asyncio.Task` — корутина, поставленная в цикл событий) и `Future` — низкоуровневый объект «результат будет позже». Свой класс становится awaitable, если реализует `__await__`.
</details>

<details><summary>Что произойдёт, если вызвать корутину без await?</summary>

Создастся объект корутины, но тело не выполнится. Код получит этот объект вместо результата и, скорее всего, упадёт дальше. При удалении невыполненной корутины Python выдаст `RuntimeWarning: coroutine '…' was never awaited`.
</details>
