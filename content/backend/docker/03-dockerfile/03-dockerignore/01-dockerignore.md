## Теория
`COPY . .` копирует в образ **всё** из папки проекта. А в ней, кроме кода, лежат: `.git` с историей (иногда сотни мегабайт), `venv` с пакетами для вашей системы, `__pycache__`, `media` с загруженными фото и — хуже всего — `.env` с паролями. Всё это уходит в контекст сборки, раздувает образ и попадает в реестр, откуда образ скачивают другие.

**`.dockerignore`** — файл в корне контекста сборки (рядом с Dockerfile), похожий на `.gitignore`: какие файлы и папки **не** отправлять сборщику. То, чего нет в контексте, не попадёт в образ ни через `COPY . .`, ни случайно.

Синтаксис:
- одна строка — один шаблон: `.git`, `.env`, `venv/`, `*.pyc`;
- `**` — любые вложенные папки: `**/__pycache__`;
- `!` — исключение из исключения: `*.md` и `!README.md`;
- `#` — комментарий.

Что обычно исключают в Django-проекте:
- `.git`, `.gitignore` — история не нужна в образе;
- `.env`, `.env.*` — секреты передают при запуске (тема 2.02);
- `venv/`, `.venv/` — в образе пакеты ставит `pip install`, а чужой `venv` с вашего компьютера ещё и сломается внутри Linux-контейнера;
- `__pycache__/`, `*.pyc` — байткод создастся заново;
- `media/` — загрузки пользователей хранят в томе, а не в образе;
- `node_modules/`, `.idea/`, `.vscode/`, `*.sqlite3`, `docker-compose*.yml` — по ситуации.

Бонус для кэша: файлы, которые меняются сами (`.git`, `__pycache__`), больше не сбрасывают кэш шага `COPY . .` (тема 3.02).

## На практике
Задача: найти, что лишнее попадает в образ магазина, и исключить это. В проекте из прошлых тем появились `.git`, `venv` и `.env`. Команды выполнены на Ubuntu 24.04 с Docker Engine 29 (имена образов в выводе заменены на учебные).

### Шаг 1. Сборка без .dockerignore
Строки про контекст в выводе сборки:
```bash
docker build -t shop-web:fat .
```
Результат (остальные шаги сокращены):
```
#3 [internal] load .dockerignore
#3 transferring context: 2B done
#3 DONE 0.0s

#5 [internal] load build context
#5 transferring context: 15.21MB 0.1s done
#5 DONE 0.1s
```
`.dockerignore` пустой, сборщику ушло 15 МБ вместо пары килобайт кода.

### Шаг 2. Что внутри образа
Смотрим содержимое рабочей папки образа:
```bash
docker run --rm shop-web:fat sh -c "ls -a /app && cat /app/.env && du -sh /app"
```
Результат:
```
.
..
.env
.git
Dockerfile
requirements.txt
shop
venv
SECRET_KEY=django-insecure-7f3k
POSTGRES_PASSWORD=s3cr3t
18M	/app
```
В образе история git, локальный `venv` и **секреты**. Любой, кто скачает образ из реестра, прочитает пароль одной командой.

### Шаг 3. Файл .dockerignore
Рядом с Dockerfile — файл `.dockerignore`:
```
.git
.env
venv/
__pycache__/
*.pyc
```
Собираем снова и смотрим контекст:
```bash
docker build -t shop-web:slim .
```
Результат (остальные шаги сокращены):
```
#3 [internal] load .dockerignore
#3 transferring context: 75B done
#3 DONE 0.0s

#5 [internal] load build context
#5 transferring context: 229B 0.0s done
#5 DONE 0.0s
```
Контекст — 229 байт: только код, `Dockerfile` и сам `.dockerignore`.

### Шаг 4. Секретов больше нет
Содержимое образа и попытка прочитать `.env`:
```bash
docker run --rm shop-web:slim sh -c "ls -a /app && du -sh /app"
docker run --rm shop-web:slim cat /app/.env
```
Результат:
```
.
..
.dockerignore
Dockerfile
requirements.txt
shop
24K	/app
cat: /app/.env: No such file or directory
```
В рабочей папке 24 КБ вместо 18 МБ, `.env` в образ не попал. Секреты передаются при запуске: `docker run --env-file .env …`.

## Частые ошибки
- **Нет `.dockerignore`.** `.env` с паролями, `.git` и `venv` уходят в образ и в реестр. Создавайте его вместе с Dockerfile.
- **`.dockerignore` не в той папке.** Он работает только в корне **контекста** (папка из `docker build … путь`), а не рядом с Dockerfile в другом месте.
- **Скопировали `venv` в образ.** Пакеты собраны под ваш компьютер (а то и под macOS) — в Linux-контейнере ломаются. В образе зависимости ставит `pip install`.
- **Исключили нужное.** `*.txt` убрал и `requirements.txt` — `COPY requirements.txt .` падает с `not found`. Возвращайте исключением: `!requirements.txt`.
- **Считать `.dockerignore` защитой уже опубликованного образа.** Если `.env` однажды попал в образ в реестре, его оттуда уже скачали. Меняйте сами секреты.
- **Путать с `.gitignore`.** Это разные файлы: git может хранить `Dockerfile` и `docker-compose.yml`, а в образ они не нужны, и наоборот.

## Итог
**Зачем**
- Не отправлять сборщику и не класть в образ лишнее: `.git`, `venv`, `.env`, `__pycache__`, `media`.

**Как**
- Файл `.dockerignore` в корне контекста; шаблоны как в `.gitignore`, `**` — вложенные, `!` — исключение.

**Польза**
- Меньше контекст и образ, нет секретов в образе, стабильнее кэш `COPY . .`.

## Вопросы на собеседовании
<details><summary>Зачем нужен `.dockerignore`?</summary>

Он исключает файлы из контекста сборки. Это ускоряет отправку контекста, уменьшает образ, не даёт случайно положить в образ секреты (`.env`, ключи) и локальные артефакты (`venv`, `.git`, `__pycache__`), а также делает кэш шага `COPY . .` стабильнее.
</details>

<details><summary>Что будет, если `.env` попал в опубликованный образ?</summary>

Его может прочитать любой, кто скачал образ: `docker run образ cat .env` или распаковав слои. Удаление файла в новой версии образа не помогает — старые версии и слои остаются в реестре и у тех, кто их скачал. Нужно сменить все секреты из файла и добавить `.env` в `.dockerignore`.
</details>
