## Теория
`cat` выводит файл целиком — для `.env` из пяти строк это удобно, а лог за месяц — сотни тысяч строк, они пролетят по экрану. Для логов и больших файлов есть свои команды:
- **`head -n N файл`** — первые N строк (без `-n` — 10);
- **`tail -n N файл`** — последние N строк. Новые записи лог дописывает в конец, поэтому самое свежее — в `tail`;
- **`tail -f файл`** — показать конец и **следить**: новые строки появляются на экране, как только программа их записала. Выход — `Ctrl+C`. Главный способ смотреть, что происходит с сайтом прямо сейчас;
- **`wc -l файл`** — сколько строк в файле;
- **`less файл`** — листать файл постранично, не загружая его целиком: стрелки и `Space` — вниз, `b` — вверх, `G` — в конец, `g` — в начало, `/текст` — поиск вперёд, `n` — следующее совпадение, `q` — выход.

Команды можно соединять конвейером `|` (подробно — раздел «Поиск и обработка текста»): `head -n 12 app.log | tail -n 2` — строки 11 и 12.

Логи на сервере часто закрыты от обычных пользователей: журналы Nginx принадлежат `root`, и `tail` ответит `Permission denied`. Тогда — `sudo tail …`.

Строка лога приложения магазина выглядит так: дата и время, уровень (`INFO`, `WARNING`, `ERROR`), сообщение. Ошибки сайта — строки `ERROR`.

## На практике
Задача: покупатели пишут, что не могут оформить заказ. Смотрим лог приложения `/var/log/shop/app.log` и лог Nginx.

### Шаг 1. Размер и начало лога
Сколько строк и с чего начинается:
```bash
cd /var/log/shop
wc -l app.log
head -n 3 app.log
```
Результат:
```
22 app.log
2026-11-21 09:10:00 INFO Booting worker with pid: 812
2026-11-21 09:12:07 INFO GET /catalog/ 200
2026-11-21 09:14:14 INFO GET /product/2/ 200
```
В начале — запуск воркера Gunicorn. Для поиска свежей ошибки начало не нужно.

### Шаг 2. Последние записи
Конец лога:
```bash
tail -n 5 app.log
```
Результат:
```
2026-11-21 09:44:59 INFO GET /product/8/ 200
2026-11-21 09:46:06 ERROR Internal Server Error: /checkout/
2026-11-21 09:48:13 INFO GET /cart/ 200
2026-11-21 09:50:20 INFO POST /checkout/ 302
2026-11-21 09:52:27 INFO GET /orders/126/ 200
```
В 09:46 оформление заказа упало с ошибкой 500. Сохраним последние 20 строк для разработчика:
```bash
tail -n 20 app.log > ~/last20.log
wc -l ~/last20.log
```
Результат:
```
20 /home/shop/last20.log
```

### Шаг 3. Лог Nginx — нужен sudo
Лог Nginx закрыт для пользователя `shop`:
```bash
tail -n 3 /var/log/nginx/access.log
sudo tail -n 3 /var/log/nginx/access.log
```
Результат:
```
tail: cannot open '/var/log/nginx/access.log' for reading: Permission denied
198.51.100.23 - - [21/Nov/2026:09:45:05 +0300] "GET /catalog/ HTTP/1.1" 200 5120
93.184.216.34 - - [21/Nov/2026:09:46:18 +0300] "GET /product/2/ HTTP/1.1" 200 4380
203.0.113.7 - - [21/Nov/2026:09:47:31 +0300] "POST /checkout/ HTTP/1.1" 500 145
```
Строка access.log: IP клиента, время, запрос, код ответа, размер ответа в байтах. `POST /checkout/` — 500: Nginx подтверждает ошибку приложения.

### Шаг 4. Следить в реальном времени
Пока покупатель снова оформляет заказ, следим за логом (`tail -f` на настоящем Ubuntu, в тренажёре его нет):
```bash
tail -n 2 -f /var/log/shop/app.log
```
Результат (две последние строки, затем новые по мере записи; остановлено `Ctrl+C`):
```
2026-11-21 09:50:20 INFO POST /checkout/ 302
2026-11-21 09:52:27 INFO GET /orders/126/ 200
2026-11-21 09:54:34 INFO GET /catalog/ 200
2026-11-21 09:54:41 ERROR Internal Server Error: /checkout/
^C
```
Ошибка воспроизвелась в момент действия покупателя — значит, дело не в старой записи. Причину будем искать по всему логу командой `grep` (раздел «Поиск и обработка текста»).

## Частые ошибки
- **`cat` большого лога.** Терминал «зависает», прокручивая миллионы строк. `tail -n`, `less`.
- **Искать свежее в `head`.** Новые записи — в конце файла; `head` показывает самые старые.
- **Ждать, что `tail -f` закончится сам.** Он следит бесконечно; выход — `Ctrl+C` (а не `q`, как в `less`).
- **Открыть большой лог в редакторе.** `nano` загружает файл целиком в память; для просмотра — `less`.
- **`sudo` ко всему подряд.** Нужен только там, где `Permission denied`; читать свой `.env` — без `sudo`.
- **Смотреть не тот лог.** Ошибка 502 — в логе Nginx (`/var/log/nginx/error.log`), а ошибка в коде view — в логе приложения.

## Итог
**Команды**
- `head -n N` — начало, `tail -n N` — конец, `tail -f` — следить (`Ctrl+C`), `wc -l` — строк, `less` — листать (`/`, `n`, `G`, `q`).

**Логи**
- Свежее — в конце; закрытые логи — `sudo tail`; строки `ERROR` и коды 5xx — следы ошибок.

## Вопросы на собеседовании
<details><summary>Как посмотреть последние строки лога и следить за новыми?</summary>

`tail -n 100 файл` — последние 100 строк, `tail -f файл` — вывести конец и дописывать новые строки по мере их появления. `tail -F` дополнительно переоткрывает файл, если его заменили при ротации логов.
</details>

<details><summary>Чем `less` лучше `cat` для больших файлов?</summary>

`less` показывает файл постранично и читает его по мере прокрутки, не выводя всё в терминал: можно листать вперёд и назад, искать (`/текст`, `n`), переходить в конец (`G`). `cat` выводит файл целиком — для логов в миллионы строк это бесполезно.
</details>

<details><summary>Как вывести строки с 11 по 20?</summary>

`head -n 20 файл | tail -n 10` — первые 20 строк, из них последние 10. Другой способ — `sed -n '11,20p' файл`.
</details>
