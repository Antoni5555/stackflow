## Теория
На своём компьютере проект лежал в домашней папке (курс «Терминал и Git: старт»). На сервере всё устроено по общему для Linux порядку — **иерархии файловой системы** (FHS): у каждой папки от корня `/` своё назначение, и, зная его, на любом сервере сразу понятно, где искать.

Папки, с которыми работает backend-разработчик:
- **`/etc`** — настройки системы и программ: `/etc/nginx/` (веб-сервер), `/etc/systemd/system/` (сервисы), `/etc/hosts`. Только текстовые файлы, менять — через `sudo`;
- **`/var`** — данные, которые меняются во время работы: **`/var/log`** — журналы (логи) программ, `/var/lib` — данные служб (база PostgreSQL — `/var/lib/postgresql`), `/var/www` — сайты по умолчанию для Nginx;
- **`/srv`** — данные сервисов этого сервера: сюда удобно класть сайт — `/srv/shop`;
- **`/home`** — домашние папки пользователей: `/home/shop` (сокращённо `~`), у администратора `root` — своя `/root`;
- **`/tmp`** — временные файлы: писать может любой пользователь, очищается при перезагрузке;
- **`/usr`** — установленные программы: `/usr/bin/python3`, `/usr/bin/git`; `/opt` — программы, поставленные вручную, не из пакетов;
- **`/bin`**, **`/dev`**, **`/proc`**, **`/boot`** — сама система: команды, устройства, процессы, загрузка. Их не трогают.

В Linux всё — файлы в одном дереве: нет дисков `C:` и `D:`, второй диск подключается папкой внутри дерева (например, `/mnt/data`).

Магазин на сервере этого курса устроен так: код — `/srv/shop`, фото товаров — `/srv/shop/media/products`, логи приложения — `/var/log/shop`, логи и настройки Nginx — `/var/log/nginx` и `/etc/nginx`, домашняя папка пользователя `shop` — `/home/shop`. Пользователь `shop` хозяин своих папок, а `/etc` и `/var/log` принадлежат `root` — туда без `sudo` не написать (раздел «Пользователи и права»).

## На практике
Задача: вы впервые зашли на сервер магазина под пользователем `shop` — найти код, логи и настройки. Команды выполнены в терминале сервера.

### Шаг 1. Где мы и что в корне
После входа терминал открывается в домашней папке:
```bash
pwd
ls /
```
Результат:
```
/home/shop
bin  dev  etc  home  opt  root  srv  tmp  usr  var
```
На настоящем Ubuntu в корне больше папок (`boot`, `lib`, `proc`, `run`, `sys`…) — это система, нам нужны `srv`, `var`, `etc`.

### Шаг 2. Код и логи
Код магазина и скрытый `.env`:
```bash
ls -a /srv/shop
```
Результат:
```
.  ..  .env  manage.py  media  shop
```
Логи приложения и Nginx — двумя путями в одной команде:
```bash
ls /var/log/shop /var/log/nginx
```
Результат:
```
/var/log/shop:
app.log

/var/log/nginx:
access.log  error.log
```

### Шаг 3. Настройки и программы
Настройки Nginx:
```bash
ls /etc/nginx
```
Результат:
```
nginx.conf  sites-available  sites-enabled
```
Где лежит программа — команда `which` (ищет по папкам из `PATH`):
```bash
which python3 ls
```
Результат:
```
/usr/bin/python3
/usr/bin/ls
```

### Шаг 4. Куда можно писать
Пользователь `shop` пробует создать файл в логах и во временной папке:
```bash
touch /var/log/shop/new.log
touch /tmp/x.txt
```
Результат:
```
touch: cannot touch '/var/log/shop/new.log': Permission denied
```
В `/var/log/shop` пишет только `root` (и программы, которые от его имени работают), а в `/tmp` — любой. Ошибка `Permission denied` — не поломка, а защита системы: менять системные папки — через `sudo`.

## Частые ошибки
- **Код сайта в `/root` или `/tmp`.** В `/root` у веб-сервера нет доступа, `/tmp` очищается при перезагрузке. Код — в `/srv/<проект>` или домашней папке пользователя сайта.
- **Искать логи рядом с кодом.** На сервере их пишут в `/var/log/<программа>`: логи Nginx — `/var/log/nginx`, а не в папке проекта.
- **Менять файлы в `/usr/bin` или `/bin`.** Это программы из пакетов — обновление перезапишет изменения. Своё — в `/opt` или `/usr/local`.
- **Путать `/` и `~`.** `cd /` — корень всей системы, `cd ~` — домашняя папка; `rm -r ~/backups` и `rm -r /backups` — разные папки.
- **Хранить секреты в `/tmp`.** Папку читают все пользователи сервера. Временный дамп базы — в домашнюю папку с закрытыми правами.

## Итог
**Дерево**
- Всё от `/`; дисков-букв нет, диски подключаются папками.

**Папки**
- `/etc` — настройки, `/var/log` — логи, `/var/lib` — данные служб, `/srv` — сайт, `/home` — пользователи, `/tmp` — временное, `/usr/bin` — программы.

**Магазин**
- Код `/srv/shop`, логи `/var/log/shop` и `/var/log/nginx`, настройки `/etc/nginx`; в системные папки — только через `sudo`.

## Вопросы на собеседовании
<details><summary>Что лежит в `/etc`, `/var` и `/usr`?</summary>

`/etc` — конфигурационные файлы системы и программ (текстовые). `/var` — изменяемые данные: логи (`/var/log`), данные служб (`/var/lib`), очереди и кэши. `/usr` — установленные программы и их библиотеки (`/usr/bin`, `/usr/lib`), в обычной работе только читается.
</details>

<details><summary>Где искать логи Nginx и приложения на сервере?</summary>

По умолчанию — `/var/log/nginx/access.log` и `/var/log/nginx/error.log`; путь задают директивы `access_log` и `error_log` в `/etc/nginx`. Логи приложения — там, куда их пишет настройка логирования (часто `/var/log/<проект>`); логи сервисов systemd — в журнале, `journalctl -u <сервис>`.
</details>

<details><summary>Чем `/tmp` отличается от остальных папок?</summary>

Писать в `/tmp` может любой пользователь, но удалять чужие файлы нельзя (особый бит sticky — `t` в правах `drwxrwxrwt`). Содержимое очищается при перезагрузке, поэтому там не хранят ничего ценного и секретного.
</details>
