## Теория
Скрипт из прошлой темы с опечаткой в имени папки напечатал «Готово» и вернул код `0`, хотя архива нет. Ночью по расписанию такую ошибку никто не увидит. Скрипт должен сам проверять, что всё в порядке, а при ошибке — **останавливаться с ненулевым кодом**. А старые архивы — удалять сам, иначе бэкапы съедят диск.

**Код выхода** — число, которое возвращает каждая команда: `0` — успех, любое другое — ошибка (`$?` — код последней). На кодах построены и `&&`/`||`, и `if`.

**`if`** выполняет команду и смотрит на её код:
```bash
if команда; then
    # код 0
elif другая_команда; then
    # первая не 0, а эта — 0
else
    # все не 0
fi
```
Чаще всего команда — **`[ … ]`** (то же, что `test`): она ничего не печатает, только возвращает 0 или 1. Пробелы после `[` и перед `]` обязательны: `[` — это команда, а `]` — её последний аргумент.

**Таблица 1.** Проверки в `[ ]`.

| Проверка | Истинна, если |
|---|---|
| `[ -f путь ]` | есть обычный файл |
| `[ -d путь ]` | есть папка |
| `[ -e путь ]` | есть что угодно |
| `[ -s путь ]` | файл есть и не пустой |
| `[ -z "$X" ]` / `[ -n "$X" ]` | строка пустая / не пустая |
| `[ "$A" = "$B" ]`, `!=` | строки равны / не равны |
| `[ "$N" -eq 0 ]`, `-ne -lt -le -gt -ge` | числа: =, ≠, <, ≤, >, ≥ |
| `[ ! … ]` | отрицание |

**`exit N`** завершает скрипт с кодом `N`: `exit 1` — «ошибка». Сообщения об ошибках пишут в поток ошибок: `echo "…" >&2` — так их видно, даже когда обычный вывод ушёл в файл.

**`for`** повторяет команды для каждого слова списка:
```bash
for f in ~/backups/*.tar.gz; do
    echo "архив: $f"
done
```
Шаблон `*.tar.gz` раскрывается в список файлов. Если ни один файл не подошёл, bash оставляет сам шаблон — в `$f` окажется строка `*.tar.gz`.

**Удалить старые файлы** можно циклом с проверкой даты, но проще одной командой: `find папка -name '*.tar.gz' -mtime +7 -delete` (`-mtime` — раздел 2). Перед `-delete` запускают ту же команду без него — посмотреть, что будет удалено.

| Задача | Как |

## На практике
Задача: научить скрипт бэкапа проверять аргумент и результат `tar`, а потом убрать старые архивы. Команды выполнены на настоящем Ubuntu (bash 5.2) от пользователя `shop`.

### Шаг 1. Коды выхода
Папка с опечаткой и без:
```bash
ls /srv/shop/medai
echo $?
[ -d /srv/shop/media ]
echo $?
```
Результат:
```
ls: cannot access '/srv/shop/medai': No such file or directory
2
0
```
`[ -d … ]` ничего не напечатал — ответ только в коде: `0` — папка есть.

### Шаг 2. Скрипт с проверками
Новая версия. Файл `~/bin/backup.sh`:
```bash
#!/bin/bash
# Бэкап папки магазина: ./backup.sh media
DEST=/home/shop/backups

if [ -z "$1" ]; then
    echo "Использование: $0 папка" >&2
    exit 1
fi

if [ ! -d "/srv/shop/$1" ]; then
    echo "Нет папки /srv/shop/$1" >&2
    exit 1
fi

NAME="$1-$(date +%F).tar.gz"
mkdir -p "$DEST"
if tar -czf "$DEST/$NAME" -C /srv/shop "$1"; then
    echo "Готово: $DEST/$NAME"
else
    echo "Ошибка: архив не создан" >&2
    exit 1
fi
```
Три запуска — без аргумента, с опечаткой и правильный:
```bash
./backup.sh
echo $?
./backup.sh medai
echo $?
./backup.sh media
echo $?
```
Результат:
```
Использование: ./backup.sh папка
1
Нет папки /srv/shop/medai
1
Готово: /home/shop/backups/media-2026-11-23.tar.gz
0
```
Теперь ошибка видна и по коду: cron, systemd или `&&` в другом скрипте поймут, что бэкап не удался.

### Шаг 3. Цикл по архивам
В `~/backups` накопились архивы за месяц:
```bash
cd ~/backups
for f in *.tar.gz; do echo "архив: $f"; done
```
Результат:
```
архив: media-2026-11-01.tar.gz
архив: media-2026-11-05.tar.gz
архив: media-2026-11-10.tar.gz
архив: media-2026-11-12.tar.gz
архив: media-2026-11-14.tar.gz
архив: media-2026-11-16.tar.gz
архив: media-2026-11-18.tar.gz
архив: media-2026-11-20.tar.gz
архив: media-2026-11-21.tar.gz
архив: media-2026-11-22.tar.gz
архив: media-2026-11-23.tar.gz
```
Цикл одной строкой — через `;`: перед `do` и перед `done`.

### Шаг 4. Удалить архивы старше 7 дней
Сначала — что попадёт под удаление (`sort` — чтобы по порядку, `find` выдаёт файлы как придётся):
```bash
find ~/backups -name '*.tar.gz' -mtime +7 | sort
```
Результат:
```
/home/shop/backups/media-2026-11-01.tar.gz
/home/shop/backups/media-2026-11-05.tar.gz
/home/shop/backups/media-2026-11-10.tar.gz
/home/shop/backups/media-2026-11-12.tar.gz
/home/shop/backups/media-2026-11-14.tar.gz
```
Список верный — удаляем и смотрим, что осталось:
```bash
find ~/backups -name '*.tar.gz' -mtime +7 -delete
ls ~/backups
```
Результат:
```
media-2026-11-16.tar.gz
media-2026-11-18.tar.gz
media-2026-11-20.tar.gz
media-2026-11-21.tar.gz
media-2026-11-22.tar.gz
media-2026-11-23.tar.gz
notes.txt
```
`-mtime +7` — больше 7 **полных** суток: архив от 16-го (ровно 7 суток) остался. `notes.txt` не тронут — его не берёт `-name '*.tar.gz'`. Эту строку дописывают в конец `backup.sh` — и каждый бэкап сам убирает старые.

### Шаг 5. Ошибки в `[ ]`
Самые частые ошибки — пропущенный пробел и сравнение чисел знаком `>`:
```bash
X=media
[ -z "$X"]
[-z "$X" ]
[ 10 > 7 ]
ls
```
Результат:
```
bash: [: missing `]'
bash: [-z: command not found
7
```
`[ 10 > 7 ]` не сравнил числа: `>` — перенаправление, и bash создал файл `7`. Числа сравнивают `-gt`, `-lt`.

## Частые ошибки
- **Нет пробелов в `[ ]`.** `[-f x ]` — `[-f: command not found`, `[ -f x]` — ошибка про недостающую `]`. Пробел после `[` и перед `]`.
- **`>` и `<` для чисел.** `[ 10 > 7 ]` создаёт файл `7` и всегда «истинно». Числа — `-gt`, `-lt`, `-eq`; `=` — для строк.
- **Переменная без кавычек в `[ ]`.** Пустая — проверка ломается или врёт, с пробелом — `[: too many arguments`. Всегда `[ -z "$1" ]`.
- **Забыть `exit 1`.** Скрипт напечатал ошибку и пошёл дальше. После сообщения об ошибке — `exit 1`, иначе код останется `0`.
- **`-delete` без пробного запуска.** Ошибка в `-name` или папке — и удалено не то. Сначала без `-delete`, потом с ним. И `-delete` — последним: `find . -delete -name '*.gz'` удалит всё.
- **`for f in $(ls)`.** Имена с пробелами разваливаются на части. Шаблон `for f in *.tar.gz` работает с любыми именами.
- **Забыть `fi`, `then`, `do` или `;`.** `syntax error near unexpected token` или `unexpected end of file`. В одну строку: `if …; then …; fi`, `for …; do …; done`.

## Итог
**Коды выхода**
- 0 — успех; `$?` — код последней команды; `exit 1` — выйти с ошибкой.

**if**
- `if команда; then … elif …; else …; fi` — по коду команды.
- `[ -f ]`, `[ -d ]`, `[ -z "$X" ]`, `=`/`!=` для строк, `-eq -gt -lt` для чисел; пробелы внутри `[ ]`.

**for и уборка**
- `for f in *.tar.gz; do …; done`.
- `find папка -name '*.tar.gz' -mtime +7` → проверить → `-delete`.

## Вопросы на собеседовании
<details><summary>Что такое код выхода и как его использует `if`?</summary>

Каждая программа при завершении возвращает число: 0 — успех, остальное — ошибка. `if` запускает команду и выбирает ветку по её коду; `[ … ]` — тоже команда, которая только возвращает 0 или 1. Так же работают `&&` (следующая — при 0) и `||` (при не 0).
</details>

<details><summary>Чем `[ ]` отличается от `[[ ]]`?</summary>

`[` — обычная команда (`test`), поэтому нужны пробелы и кавычки вокруг переменных, а `>` — перенаправление. `[[ ]]` — встроенный синтаксис bash: переменные не делятся по пробелам, есть `&&`, `||`, шаблоны (`== *.gz`) и регулярные выражения (`=~`). `[[ ]]` есть только в bash — в `sh` его нет.
</details>

<details><summary>Как сделать, чтобы скрипт останавливался на первой ошибке?</summary>

`set -e` в начале: скрипт завершится, как только команда вернёт не 0 (кроме проверок в `if`, `&&`, `||`). Часто пишут `set -euo pipefail`: `-u` — ошибка при обращении к незаданной переменной, `-o pipefail` — конвейер падает, если упала любая его часть. Проверки с понятным сообщением (`if …; then echo …; exit 1; fi`) всё равно нужны — `set -e` только останавливает.
</details>
