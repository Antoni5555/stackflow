## Теория
Бэкап фото магазина — это несколько команд: создать папку, упаковать `media` в архив с датой, сообщить, что готово. Набирать их руками каждый вечер долго, и рано или поздно ошибёшься в имени. **Скрипт** — текстовый файл с этими командами: bash выполняет его строку за строкой, как если бы вы набирали их сами.

Из чего состоит скрипт:
- **shebang** — первая строка `#!/bin/bash`: какой программой выполнять файл. Только самая первая строка, без пустых строк и пробелов перед ней;
- **комментарии** — всё после `#` до конца строки;
- **переменные** — `ИМЯ=значение` **без пробелов** вокруг `=`; значение — `$ИМЯ` или `${ИМЯ}`, когда сразу за именем идут буквы: `${NAME}_db`;
- **аргументы** — слова после имени скрипта: `$1`, `$2`… — первый, второй; `$0` — как вызвали скрипт; `$#` — сколько аргументов; `"$@"` — все;
- **подстановка команды** — `$(команда)` заменяется её выводом: `$(date +%F)` → `2026-11-23`.

Кавычки:
- `"…"` — переменные и `$(…)` подставляются, а значение остаётся **одним словом**, даже с пробелами. Переменные в скриптах всегда пишут в двойных кавычках: `"$1"`, `"$DEST/$NAME"`;
- `'…'` — текст как есть, `$` не работает.

Как запустить:
- **`./backup.sh`** — нужны право на выполнение (`chmod +x`, раздел 3) и shebang. `./` — «из текущей папки»: текущей папки нет в `PATH`, и просто `backup.sh` даст `command not found`;
- **`bash backup.sh`** — bash сам читает файл; `+x` не нужен;
- **по имени** — `backup.sh` из любой папки, если скрипт лежит в папке из `PATH` (например `~/bin`, прошлый раздел).

Скрипт выполняется в **отдельной** оболочке: его переменные и `cd` не меняют ваш терминал. Код выхода скрипта — код его **последней** команды.

## На практике
Задача: написать скрипт, который упаковывает папку магазина в архив с датой в имени. Команды выполнены на настоящем Ubuntu (bash 5.2) от пользователя `shop`.

### Шаг 1. Файл скрипта
Создаём `~/bin/backup.sh` (в `nano` или любом редакторе). Файл `~/bin/backup.sh`:
```bash
#!/bin/bash
# Бэкап папки магазина: архив с датой в имени
DEST=/home/shop/backups
NAME="$1-$(date +%F).tar.gz"

mkdir -p "$DEST"
tar -czf "$DEST/$NAME" -C /srv/shop "$1"
echo "Готово: $DEST/$NAME"
```
`$1` — какую папку магазина упаковать (`media`, `static`), `-C /srv/shop` — `tar` переходит в папку магазина, и в архиве пути начинаются с `media/`, а не с `/srv/shop/media/`.

### Шаг 2. Запуск
Запуск до и после `chmod +x`:
```bash
cd ~/bin
./backup.sh media
chmod +x backup.sh
./backup.sh media
```
Результат:
```
bash: ./backup.sh: Permission denied
Готово: /home/shop/backups/media-2026-11-23.tar.gz
```
Новый файл создаётся без права `x` — сначала `chmod +x`. Ещё одна папка и результат:
```bash
./backup.sh static
ls -l ~/backups
```
Результат:
```
Готово: /home/shop/backups/static-2026-11-23.tar.gz
total 300
-rw-rw-r-- 1 shop shop 300344 Nov 23 03:00 media-2026-11-23.tar.gz
-rw-rw-r-- 1 shop shop    172 Nov 23 03:00 static-2026-11-23.tar.gz
```
Один скрипт — разные папки: меняется только аргумент.

### Шаг 3. Аргументы и кавычки
Маленький скрипт показывает, что он получает. Файл `~/bin/args.sh`:
```bash
#!/bin/bash
echo "скрипт: $0"
echo "первый: $1"
echo "второй: $2"
echo "всего: $#"
```
Запуск — с кавычками и без:
```bash
./args.sh media "my files"
./args.sh media my files
```
Результат:
```
скрипт: ./args.sh
первый: media
второй: my files
всего: 2
скрипт: ./args.sh
первый: media
второй: my
всего: 3
```
Кавычки при вызове сделали `my files` одним аргументом. Внутри скрипта то же самое: `tar … "$1"` передаст имя с пробелом целиком, а `tar … $1` — двумя словами.

### Шаг 4. Типичные ошибки запуска
Скрипт по имени, переменная с пробелами и одинарные кавычки:
```bash
backup.sh media
NAME = shop
echo '$NAME' "$NAME"
```
Результат:
```
bash: backup.sh: command not found
bash: NAME: command not found
$NAME
```
- без `./` bash ищет `backup.sh` в папках `PATH`, а текущей папки там нет;
- с пробелами `NAME = shop` — это запуск команды `NAME` с аргументами `=` и `shop`;
- в одинарных кавычках `$NAME` не подставился, а в двойных — пусто: переменной `NAME` так и не задали.

### Шаг 5. Скрипт врёт «Готово»
Запуск без аргумента и с опечаткой в имени папки:
```bash
./backup.sh medai
echo $?
```
Результат:
```
tar: medai: Cannot stat: No such file or directory
tar: Exiting with failure status due to previous errors
Готово: /home/shop/backups/medai-2026-11-23.tar.gz
0
```
`tar` упал, но скрипт пошёл дальше, написал «Готово» и вернул `0` — код последней команды, `echo`. Самое простое средство — `&&`: `tar … && echo "Готово: …"`. Проверять аргументы и останавливать скрипт с ошибкой (`if`, `exit 1`) — следующая тема.

## Частые ошибки
- **Пробелы вокруг `=`.** `DEST = /backups` — `DEST: command not found`. Пишут слитно: `DEST=/backups`.
- **Забыть `chmod +x`.** `./backup.sh: Permission denied` (код 126). Или `chmod +x`, или `bash backup.sh`.
- **`backup.sh` без `./`.** `command not found` (код 127): текущей папки нет в `PATH`.
- **Shebang не в первой строке.** Из терминала скрипт сработает (bash выполнит его сам), но systemd и программы на Python запускают файл напрямую — `Exec format error`, а cron выполнит его через `sh`, без возможностей bash. `#!/bin/bash` — строго первой строкой.
- **Файл сохранён в Windows.** Концы строк `CRLF`: shebang превращается в `#!/bin/bash\r` — `cannot execute: required file not found`. Сохраняют с концами строк `LF` (в VS Code — внизу справа).
- **Переменная без кавычек.** `rm -r $DIR/old` при пустом `DIR` — это `rm -r /old`, а с пробелом в значении — два разных пути. Всегда `"$DIR"`.
- **Одинарные кавычки вокруг переменной.** `echo 'Готово: $NAME'` печатает буквально `$NAME`.

## Итог
**Файл**
- `#!/bin/bash` — первой строкой; `chmod +x`; запуск `./скрипт` или `bash скрипт`.

**Переменные и аргументы**
- `ИМЯ=значение` без пробелов; значение — `"$ИМЯ"`; `$1`, `$#`, `"$@"`, `$0`.
- `$(команда)` — вывод команды: `$(date +%F)`.

**Поведение**
- Своя оболочка: переменные и `cd` не выходят наружу.
- Код выхода — от последней команды; ошибка в середине скрипт не останавливает.

## Вопросы на собеседовании
<details><summary>Что такое shebang и зачем он нужен?</summary>

Первая строка `#!путь` говорит ядру, какой программой выполнить файл, когда его запускают как программу (`./script`). `#!/bin/bash` — bash, `#!/usr/bin/env python3` — Python из `PATH`. Без shebang файл нельзя надёжно запустить из cron, systemd или другой программы.
</details>

<details><summary>Чем `./script.sh` отличается от `bash script.sh` и `source script.sh`?</summary>

`./script.sh` — запуск файла как программы: нужны право `x` и shebang. `bash script.sh` — bash читает файл как аргумент, право `x` не нужно, shebang не важен. Оба выполняют скрипт в новой оболочке. `source script.sh` (или `. script.sh`) выполняет команды в **текущей** оболочке — так переменные и `cd` остаются (так работает `source venv/bin/activate`).
</details>

<details><summary>Почему переменные в bash пишут в двойных кавычках?</summary>

Без кавычек bash делит значение по пробелам и раскрывает `*`: имя `my files` превращается в два аргумента, пустая переменная исчезает совсем, и `rm -r $DIR/` становится `rm -r /`. В двойных кавычках значение остаётся одним словом.
</details>
