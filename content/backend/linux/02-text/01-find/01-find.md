## Теория
`ls` показывает одну папку. Когда нужно найти файл где-то в дереве — по имени, типу, размеру или возрасту, — используют **`find`**:
```
find где_искать условия
```
`find` обходит папку и все вложенные и печатает пути, которые подошли под **все** условия:
- **`-name "*.jpg"`** — по имени, с шаблонами: `*` — любые символы, `?` — один символ. Регистр важен: `photo.JPG` не подойдёт под `"*.jpg"`; без учёта регистра — **`-iname`**;
- **`-type f`** — только файлы, **`-type d`** — только папки;
- **`-size +5M`** — больше 5 МБ, `-size -100k` — меньше 100 КБ (единицы `k`, `M`, `G`);
- **`-mtime +7`** — изменён больше 7 дней назад, `-mtime -1` — за последние сутки.

Шаблон в `-name` берут **в кавычки**. Без них `*.jpg` раскроет сама оболочка — по файлам текущей папки — и `find` получит не шаблон, а список имён.

Если искать от корня (`find / …`), `find` зайдёт в чужие папки и напишет `Permission denied` для каждой закрытой. Это не мешает — найденное всё равно напечатается; как убрать такие сообщения — тема «Перенаправление».

Найденное можно сразу обработать: `-delete` — удалить, `-exec команда {} \;` — выполнить команду для каждого файла (`{}` — путь). Перед `-delete` запускают ту же команду без него и смотрят список: удаление необратимо. В тренажёре этих действий нет — найденные файлы удаляют `rm`.

**Таблица 1.** Условия `find`.

| Условие | Что находит | Пример |
|---|---|---|
| `-name "шаблон"` | имя по шаблону, с учётом регистра | `-name "*.log"` |
| `-iname "шаблон"` | то же без учёта регистра | `-iname "*.jpg"` |
| `-type f` / `-type d` | файлы / папки | `-type d` |
| `-size +N` / `-size -N` | больше / меньше N (`k`, `M`, `G`) | `-size +5M` |
| `-mtime +N` / `-mtime -N` | изменён больше / меньше N дней назад | `-mtime +7` |
| `-delete` | удалить найденное (нет в тренажёре) | `… -mtime +30 -delete` |
| `-exec … {} \;` | команда для каждого (нет в тренажёре) | `-exec ls -lh {} \;` |

## На практике
Задача: место на сервере заканчивается — найти в `/srv/shop/media` тяжёлые фото товаров и забытые временные файлы загрузки. Команды выполнены в терминале сервера из `/srv/shop`; `find` печатает файлы в порядке обхода — на настоящем сервере он может отличаться.

### Шаг 1. По имени
Все фото в формате JPG:
```bash
cd /srv/shop
find media -name "*.jpg"
find media -iname "*.jpg"
```
Результат:
```
media/products/keyboard.jpg
media/products/laptop-air.jpg
media/products/mouse.jpg
media/products/headphones.JPG
media/products/keyboard.jpg
media/products/laptop-air.jpg
media/products/mouse.jpg
```
`headphones.JPG` нашёлся только с `-iname`: в Linux `JPG` и `jpg` — разные имена.

### Шаг 2. По размеру и типу
Файлы больше 5 МБ:
```bash
find media -type f -size +5M
```
Результат:
```
media/products/headphones.JPG
media/products/laptop-air.jpg
media/products/laptop-pro.png
media/tmp/upload-7f3a.part
```
Четыре кандидата на сжатие; `upload-7f3a.part` в `tmp` — недокачанная загрузка, её можно удалить.

### Шаг 3. По возрасту
Файлы, которые не менялись больше недели:
```bash
find media -type f -mtime +7
```
Результат:
```
media/products/laptop-pro.png
media/products/mouse.jpg
media/tmp/upload-7f3a.part
```
Условия складываются: `find media/tmp -type f -mtime +7` — старые временные файлы, их и удаляют по расписанию (раздел «Автоматизация»).

### Шаг 4. Шаблон без кавычек
Из папки с фото:
```bash
cd media/products
find . -name *.jpg
```
Результат (настоящий Ubuntu):
```
find: paths must precede expression: `laptop-air.jpg'
find: possible unquoted pattern after predicate `-name'?
```
Оболочка раскрыла `*.jpg` в `keyboard.jpg laptop-air.jpg mouse.jpg`, и `find` получил лишние слова. Сам `find` подсказывает: шаблон без кавычек. Правильно — `find . -name "*.jpg"`.

## Частые ошибки
- **Шаблон без кавычек.** Работает в одной папке и ломается в другой — смотря какие там файлы. Всегда `-name "*.jpg"`.
- **`-name` и регистр.** `photo.JPG` не попадёт под `"*.jpg"`. Для фото от пользователей — `-iname`.
- **`-delete` без проверки.** Сначала запуск без `-delete`, просмотр списка, потом удаление. И `-delete` — в конце: `find media -delete -name "*.part"` удалит всё.
- **`find /` без нужды.** Обход всего диска долгий и сыплет `Permission denied`. Ищут от папки, где файл может быть: `find /var/log -name "*.log"`.
- **`-size 5M` вместо `+5M`.** Без знака — «ровно 5 МБ» (с округлением вверх), почти ничего не найдётся.
- **Путать `-mtime +7` и `-7`.** `+7` — старше недели, `-7` — свежее недели.

## Итог
**Синтаксис**
- `find где условия`; условия складываются.

**Условия**
- `-name`/`-iname "шаблон"` (в кавычках), `-type f|d`, `-size +5M`, `-mtime +7`.

**Действия**
- `-delete`, `-exec … {} \;` — после проверки списка без них.

## Вопросы на собеседовании
<details><summary>Как найти файлы больше 100 МБ, изменённые больше 30 дней назад?</summary>

`find /путь -type f -size +100M -mtime +30`. Условия объединяются логическим «и»; для «или» — `\( -name "*.log" -o -name "*.gz" \)`. Чтобы увидеть размеры — `-exec ls -lh {} +` или `-printf "%s %p\n"`.
</details>

<details><summary>Почему шаблон в `find -name` нужно брать в кавычки?</summary>

Без кавычек `*` раскрывает оболочка до запуска `find` — по файлам текущей папки. Если там есть подходящие файлы, `find` получит их имена вместо шаблона: найдёт не то или упадёт с ошибкой «paths must precede expression». В кавычках шаблон передаётся `find` как есть.
</details>

<details><summary>Чем `-exec … {} \;` отличается от `-exec … {} +`?</summary>

С `\;` команда запускается отдельно для каждого найденного файла. С `+` `find` собирает пути и передаёт их пачками в один запуск команды — быстрее на тысячах файлов. Тот же эффект даёт `find … -print0 | xargs -0 команда`.
</details>
