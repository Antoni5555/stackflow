## Теория
Бэкап папки с фото товаров, перенос проекта на другой сервер, отправка логов разработчику — всё это удобнее одним файлом. В Linux для этого две программы:
- **`tar`** — склеивает папки и файлы в один архив (`.tar`), сохраняя пути, права и владельцев;
- **`gzip`** — сжимает **один** файл (`app.log` → `app.log.gz`), `gunzip` — распаковывает.

Обычно их используют вместе: `tar` с ключом `z` сжимает архив через gzip — получается `.tar.gz` (или `.tgz`).

Ключи `tar` — буквы, которые пишут слитно:
- **`c`** — создать (create), **`x`** — распаковать (extract), **`t`** — показать содержимое (list);
- **`z`** — сжатие gzip;
- **`f имя`** — файл архива; `f` ставят **последним**, сразу за ним — имя архива;
- **`v`** — печатать каждый файл (verbose).

Шаблоны:
- `tar -czf архив.tar.gz папка` — упаковать;
- `tar -tzf архив.tar.gz` — посмотреть, что внутри, ничего не распаковывая;
- `tar -xzf архив.tar.gz` — распаковать **в текущую папку**; в другую — `-C папка`.

Пути внутри архива — такие, как их передали: `tar -czf … media` из `/srv/shop` сохранит `media/products/…`. Поэтому архивируют из родительской папки по относительному пути. Абсолютный путь `tar` обрезает до относительного и предупреждает: `Removing leading '/' from member names` — иначе при распаковке архив мог бы перезаписать системные файлы.

Сжатие помогает тексту: логи и дампы базы ужимаются в разы. Фото JPG и PNG уже сжаты — архив с ними почти не уменьшится, зато соберётся в один файл.

Имя архива с датой — `media-2026-11-21.tar.gz` — чтобы бэкапы не перезаписывали друг друга (дату подставляет скрипт — раздел «Автоматизация»).

**Таблица 1.** Команды архивов.

| Задача | Команда |
|---|---|
| упаковать папку со сжатием | `tar -czf media.tar.gz media` |

## На практике
Задача: сделать бэкап фото товаров магазина в `~/backups` и проверить, что его можно восстановить. Команды выполнены в терминале сервера, пользователь `shop`.

### Шаг 1. Упаковать
Из папки проекта — относительный путь `media`:
```bash
cd /srv/shop
tar -czf ~/backups/media-2026-11-21.tar.gz media
ls ~/backups
```
Результат:
```
media-2026-11-21.tar.gz
```

### Шаг 2. Проверить, что внутри
Список без распаковки:
```bash
tar -tzf ~/backups/media-2026-11-21.tar.gz
```
Результат:
```
media/
media/products/
media/products/headphones.JPG
media/products/keyboard.jpg
media/products/laptop-air.jpg
media/products/laptop-pro.png
media/products/mouse.jpg
media/tmp/
media/tmp/upload-7f3a.part
```
Пути начинаются с `media/` — при распаковке появится папка `media` там, где запустили `tar -x`.

### Шаг 3. Восстановить в другом месте
Пробное восстановление — в `/tmp`, чтобы не задеть настоящие фото:
```bash
cd /tmp
tar -xzf ~/backups/media-2026-11-21.tar.gz
ls /tmp/media/products
```
Результат:
```
headphones.JPG  keyboard.jpg  laptop-air.jpg  laptop-pro.png  mouse.jpg
```
Бэкап, который ни разу не распаковывали, — не бэкап: проверка восстановления — часть работы.

### Шаг 4. Абсолютный путь
Архив кода по абсолютному пути:
```bash
tar -czf ~/backups/code.tar.gz /srv/shop/shop
```
Результат:
```
tar: Removing leading `/' from member names
```
Внутри — `srv/shop/shop/…`; распаковка из `/tmp` создаст `/tmp/srv/shop/shop`, а не перезапишет `/srv`.

### Шаг 5. Сжать один лог
Копия лога для разработчика:
```bash
cp /var/log/shop/app.log ~/app.log
gzip ~/app.log
ls ~
```
Результат:
```
app.log.gz  backups
```
`gzip` заменил `app.log` на `app.log.gz` — исходник не остаётся (на настоящем Ubuntu его сохраняет ключ `-k`). Распаковка — `gunzip ~/app.log.gz`.

## Частые ошибки
- **`f` не последним.** `tar -cfz media.tar.gz media` — архивом станет файл `z`. Порядок: `-czf имя`.
- **Распаковать не туда.** `tar -xzf` пишет в текущую папку и молча перезаписывает файлы с теми же именами. Сначала `tar -tzf`, потом `cd` в нужную папку или `-C`.
- **Забыть имя архива.** `tar -czf media` — `tar` воспримет `media` как имя архива и ругнётся, что не передано, что упаковывать.
- **Опечатка в пути.** Настоящий Ubuntu: `tar: .env-nope: Cannot stat: No such file or directory` и `Exiting with failure status due to previous errors` — архив создан без этого файла. Код выхода 2 — в скриптах его проверяют.
- **Бэкап на том же диске.** Сломается диск — пропадут и данные, и бэкап. Копию уносят на другой сервер (`scp`, раздел «Процессы, сервисы, сеть»).
- **Ждать сжатия фото.** JPG и PNG уже сжаты; место экономят удалением ненужного, а не `gzip`.

## Итог
**tar**
- `-czf архив папка` — упаковать, `-tzf` — посмотреть, `-xzf` — распаковать (в текущую или `-C`); `f` — последним.
- Пути в архиве — как переданы: архивируют относительным путём из родительской папки.

**gzip**
- Сжимает один файл и заменяет его: `gzip` / `gunzip`.

## Вопросы на собеседовании
<details><summary>Чем `tar` отличается от `gzip`?</summary>

`tar` объединяет много файлов и папок в один поток с сохранением структуры и прав, но сам по себе не сжимает. `gzip` сжимает один поток или файл. Вместе — `.tar.gz`: `tar -czf`. Другие сжатия: `-j` (bzip2), `-J` (xz) — медленнее, но плотнее; `zstd` — быстрее при похожем сжатии.
</details>

<details><summary>Как посмотреть содержимое архива, не распаковывая?</summary>

`tar -tzf archive.tar.gz` (с `v` — с правами, размерами и датами). Извлечь один файл — `tar -xzf archive.tar.gz путь/внутри/архива`.
</details>

<details><summary>Как сделать бэкап папки с датой в имени?</summary>

`tar -czf backup-$(date +%F).tar.gz папка` — `$(date +%F)` подставит дату вида `2026-11-21`. Такой бэкап запускают по расписанию (cron), старые архивы удаляют `find backups -mtime +7 -delete`, а копию отправляют на другой сервер.
</details>
