## Теория
**`grep`** выводит строки файла, в которых есть шаблон:
```
grep [ключи] шаблон файл…
```
Главный инструмент разбора логов: из тысяч строк оставить ошибки, запросы к одной странице, записи за нужную минуту.

Ключи:
- **`-i`** — без учёта регистра (`error`, `ERROR`, `Error`);
- **`-n`** — с номером строки — чтобы потом открыть это место в `less` или `nano`;
- **`-c`** — только число подходящих строк;
- **`-v`** — наоборот: строки **без** шаблона (`grep -v INFO` — всё, кроме обычных записей);
- **`-r`** — искать во всех файлах папки и вложенных: `grep -r TODO /srv/shop` — где в коде остались пометки;
- **`-E`** — расширенные регулярные выражения (`ERROR|WARNING`).

Шаблон — **регулярное выражение**; для логов хватает нескольких символов:
- `^` — начало строки: `^2026-11-21 09:4` — записи с 09:40 до 09:49;
- `$` — конец строки: `/checkout/$` — строки, которые заканчиваются на `/checkout/`;
- `.` — любой символ (поэтому точка в IP совпадёт с любым символом — для точного поиска её экранируют `\.`);
- `a|b` — «или» (с `-E`; без него — `a\|b`).

Шаблон с пробелами или спецсимволами берут **в кавычки**: `grep " 500 " access.log` — код ответа 500, а не число 500 где-нибудь в размере ответа.

Код выхода `grep`: 0 — нашёл, 1 — ничего не нашёл, 2 — ошибка (нет файла, нет прав). Им пользуются в скриптах: «если в логе есть ERROR — отправить уведомление».

## На практике
Задача: в логах магазина найти ошибки оформления заказа и посчитать их. Лог приложения — `/var/log/shop/app.log`, Nginx — `/var/log/nginx/access.log` (закрыт для `shop`).

### Шаг 1. Ошибки и их число
Строки с `ERROR` и их число:
```bash
cd /var/log/shop
grep ERROR app.log
grep -c ERROR app.log
```
Результат:
```
2026-11-21 09:22:42 ERROR Internal Server Error: /checkout/
2026-11-21 09:34:24 ERROR Internal Server Error: /checkout/
2026-11-21 09:40:45 ERROR OperationalError: connection to server at "127.0.0.1", port 5432 failed
2026-11-21 09:46:06 ERROR Internal Server Error: /checkout/
4
```
Три ошибки на `/checkout/` и одна — база данных не отвечала в 09:40.

### Шаг 2. Всё, кроме обычных записей
Строки без `INFO`:
```bash
grep -v INFO app.log
```
Результат:
```
2026-11-21 09:16:21 WARNING Not Found: /favicon.ico
2026-11-21 09:22:42 ERROR Internal Server Error: /checkout/
2026-11-21 09:28:03 WARNING Not Found: /wp-login.php
2026-11-21 09:34:24 ERROR Internal Server Error: /checkout/
2026-11-21 09:40:45 ERROR OperationalError: connection to server at "127.0.0.1", port 5432 failed
2026-11-21 09:46:06 ERROR Internal Server Error: /checkout/
```
`/wp-login.php` — боты ищут WordPress, к магазину это отношения не имеет. То же через «или»: `grep -E "ERROR|WARNING" app.log`.

### Шаг 3. Где именно и в какое время
С номерами строк и за отрезок времени:
```bash
grep -n checkout app.log
grep "^2026-11-21 09:4" app.log
```
Результат:
```
7:2026-11-21 09:22:42 ERROR Internal Server Error: /checkout/
13:2026-11-21 09:34:24 ERROR Internal Server Error: /checkout/
19:2026-11-21 09:46:06 ERROR Internal Server Error: /checkout/
21:2026-11-21 09:50:20 INFO POST /checkout/ 302
2026-11-21 09:40:45 ERROR OperationalError: connection to server at "127.0.0.1", port 5432 failed
2026-11-21 09:42:52 INFO GET /catalog/ 200
2026-11-21 09:44:59 INFO GET /product/8/ 200
2026-11-21 09:46:06 ERROR Internal Server Error: /checkout/
2026-11-21 09:48:13 INFO GET /cart/ 200
```
`^` привязал шаблон к началу строки: только записи 09:40–09:49, а не, например, `09:4` внутри сообщения.

### Шаг 4. Код 500 в логе Nginx
Запросы с кодом 500 — без `sudo` и с ним:
```bash
grep " 500 " /var/log/nginx/access.log
sudo grep " 500 " /var/log/nginx/access.log
```
Результат:
```
grep: /var/log/nginx/access.log: Permission denied
198.51.100.23 - - [21/Nov/2026:10:04:34 +0300] "POST /checkout/ HTTP/1.1" 500 145
203.0.113.7 - - [21/Nov/2026:10:16:16 +0300] "POST /checkout/ HTTP/1.1" 500 145
192.0.2.10 - - [21/Nov/2026:10:26:41 +0300] "POST /checkout/ HTTP/1.1" 500 145
198.51.100.23 - - [21/Nov/2026:10:38:23 +0300] "POST /checkout/ HTTP/1.1" 500 145
```
Пробелы вокруг `500` важны: без них совпал бы и размер ответа вроде `15000`.

### Шаг 5. Пометки в коде
Что разработчики оставили «на потом»:
```bash
grep -rn TODO /srv/shop/shop
```
Результат:
```
/srv/shop/shop/models.py:5:    # TODO: индекс по цене
/srv/shop/shop/views.py:5:    # TODO: проверить остаток на складе
```
С `-r` каждая строка начинается с имени файла, с `-n` — ещё и с номера строки.

## Частые ошибки
- **Шаблон без кавычек.** `grep Internal Server Error app.log` ищет `Internal` в файлах `Server`, `Error` и `app.log`. Фразу — в кавычки.
- **Регистр.** `grep error` не найдёт `ERROR`. `-i`, если регистр неизвестен.
- **Слишком общий шаблон.** `grep 500` совпадёт с размером `15000` и временем `10:50:00`. Уточнять: `" 500 "`.
- **Точка в шаблоне.** `grep 192.0.2.1` найдёт и `192.0.2.10`, и `192x0y2z1`. Точно — `grep -F` (строка без регулярных выражений) или `\.`.
- **`grep -c` и `wc -l`.** Оба считают строки, а не совпадения: строка с двумя `ERROR` — одна.
- **Забыть `-r` для папки.** `grep TODO /srv/shop` — `grep: /srv/shop: Is a directory`.

## Итог
**Ключи**
- `-i` регистр, `-n` номера, `-c` число строк, `-v` наоборот, `-r` по папке, `-E` «или».

**Шаблоны**
- `^` начало, `$` конец, `.` любой символ, `a|b`; с пробелами — в кавычках.

**Код выхода**
- 0 нашёл, 1 не нашёл, 2 ошибка.

## Вопросы на собеседовании
<details><summary>Как посчитать, сколько раз в логе встречается ошибка 500?</summary>

`grep -c '" 500 ' access.log` — число строк с кодом 500 (для формата Nginx, где код идёт после закрывающей кавычки запроса). Надёжнее разбирать по полю: `awk '$9 == 500' access.log | wc -l`.
</details>

<details><summary>Чем `grep -E` отличается от обычного `grep` и от `grep -F`?</summary>

Обычный `grep` использует базовые регулярные выражения: `|`, `+`, `?`, `()` — обычные символы, их надо экранировать. `-E` — расширенные, там эти символы работают как операторы. `-F` — без регулярных выражений вовсе: шаблон ищется как строка, быстро и без сюрпризов с `.` и `*`.
</details>

<details><summary>Как найти, в каких файлах проекта используется функция?</summary>

`grep -rn "create_order" /srv/shop --include="*.py"` — рекурсивно, с номерами строк, только Python-файлы; `-l` выведет только имена файлов. Для больших проектов быстрее `ripgrep` (`rg`).
</details>
